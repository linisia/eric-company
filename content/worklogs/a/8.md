### 실행
🛠️ 일단 기존 `scripts/` 디렉터리를 훑었는데 죄다 bash라 Python은 이 폴더에선 처음이었어요. 혹시나 해서 `python3 -c "import yaml"` 돌려보니 **PyYAML이 없더라고요** — 그래서 룰 yaml을 정통으로 읽는 대신 자체 미니 파서로 처리하기로 결정했습니다.

그래서 먼저 `sanitizer_rules.yaml`을 작성했어요. `blacklist`(자동 redact)와 `secret_keywords`(경고만) 두 갈래로 분리했고, blacklist 항목은 `'<이름> ::: <정규식>'` 한 줄 형식으로 잡아서 미니 파서가 먹기 쉽게 만들었습니다. 이어서 `sanitizer.py` 본체를 짰는데, frontmatter `공개:` 파싱 → blacklist 순차 치환(`→ [REDACTED]`) → secret_keyword 카운트(치환 X, 경고만) 순서로 흘러가고, 리포트는 stderr로, sanitized 본문은 stdout 혹은 `-o`로 빠지게 했어요.

검증 1로 log/b.md의 #1·#3을 추출해 통과시켰는데 redact 0건에 diff 차이 없음 — **클린 워크로그에서 오탐 0건 확인했습니다.** 그다음 검증 2를 일부러 위험요소 심은 합성 dirty 샘플로 돌렸는데, 여기서 **버그가 떴어요.** `api_key_var` 룰이 변수명만 먼저 치환해버려서 `ANTHROPIC_API_KEY=sk-ant-...` 의 **값이 그대로 새는** 상황이었어요. 맞게 한 건지 모르겠는데... 일단 `api_key_var` 정규식을 `(\s*[:=]\s*값)?` 까지 먹게 확장하고 `sk-ant-` 전용 룰을 따로 추가한 뒤 재실행했더니 통째로 redact되는 걸 확인했습니다. 마무리로 `sanitizer_validation_sample.md`에 검증 1·2 결과와 버그 기록을 정리해 두고 `chmod +x`까지 걸어뒀어요.

### 결과
✨ 산출물은 세 개 다 냈습니다. `scripts/sanitizer.py`는 단독 CLI 모듈로 동작하고, `scripts/sanitizer_rules.yaml`은 blacklist 7종에 secret_keywords 4종 분리해서 정리됐어요. `scripts/sanitizer_validation_sample.md`에 검증 출력 샘플 한 편 남겨뒀고요. 검증 측면에서는 b.md #1·#3에서 오탐 0건, dirty 샘플에선 blacklist 6종이 발화하고 기밀 키워드는 경고만 뜨는 것까지 확인했어요.

### 배운 점 (← dream 입력)
- **패턴/원칙:** redact 룰은 **순차 치환이라 룰 간 겹침이 누락을 만든다.** 변수명만 먹는 좁은 룰이 값까지 먹는 넓은 룰보다 먼저 돌면, 뒤 룰이 키워드를 잃고 값이 샌다. 다음에 치환 룰 셋 짤 일 있으면 "넓은 룰 먼저, 좁은 룰 나중" 순서부터 잡고 들어간다.
- **막힘 회복:** dirty 샘플로 실제 돌려보지 않았으면 값 누락을 못 잡았다. redact류는 클린 입력(오탐 체크) + dirty 입력(발화 체크) **두 방향 검증이 필수**. 한 쪽만 하면 반쪽.
- **새로 통한 것:** PyYAML 없는 환경 → 룰 파일 구조를 일부러 단순하게(키 + `- 한 줄 문자열`) 잡으면 미니 파서 20줄로 의존성 0. 외부 라이브러리 없을 때 "데이터 형식을 파서에 맞춰 단순화"하는 역방향 접근.
- **오탐 사례:** codename a/b/c/d 는 워크로그가 일상적으로 써서 전부 막으면 본문이 파괴됨 → "계정 a / account b" 매핑 패턴만 좁게 잡음. frontmatter 룰 우선순위: blacklist 는 `공개:` 값과 무관하게 무조건 redact, secret_keyword 는 `public` 이어도 경고만(이중 게이트).
