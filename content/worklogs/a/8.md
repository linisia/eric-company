### 실행
1. 기존 `scripts/` 훑음 — 죄다 bash, python은 처음. `python3 -c "import yaml"` 해보니 **PyYAML 없음** → 룰 yaml 을 자체 미니 파서로 읽기로 결정.
2. `sanitizer_rules.yaml` 작성 — `blacklist`(자동 redact)와 `secret_keywords`(경고만) 두 갈래 분리. blacklist 항목은 `'<이름> ::: <정규식>'` 한 줄 형식(미니 파서가 먹기 쉽게).
3. `sanitizer.py` 작성 — frontmatter `공개:` 파싱 → blacklist 순차 치환(`→ [REDACTED]`) → secret_keyword 카운트(치환 X, 경고만). 리포트는 stderr, sanitized 본문은 stdout/`-o`.
4. 검증 1: log/b.md #1·#3 추출해 통과 → redact 0, diff 차이 없음. **클린 워크로그 오탐 0 확인.**
5. 검증 2: 위험요소 심은 합성 dirty 샘플 → **버그 발견.** `api_key_var` 룰이 변수명만 먼저 치환해서 `ANTHROPIC_API_KEY=sk-ant-...` 의 **값이 샘.** → `api_key_var` 정규식을 `(\s*[:=]\s*값)?` 까지 먹게 확장 + `sk-ant-` 전용 룰 추가 → 재실행 시 통째로 redact 확인.
6. `sanitizer_validation_sample.md` 에 검증 1·2 + 버그 기록 정리. `chmod +x`.

### 배운 점 (← dream 입력)
- **패턴/원칙:** redact 룰은 **순차 치환이라 룰 간 겹침이 누락을 만든다.** 변수명만 먹는 좁은 룰이 값까지 먹는 넓은 룰보다 먼저 돌면, 뒤 룰이 키워드를 잃고 값이 샌다. 다음에 치환 룰 셋 짤 일 있으면 "넓은 룰 먼저, 좁은 룰 나중" 순서부터 잡고 들어간다.
- **막힘 회복:** dirty 샘플로 실제 돌려보지 않았으면 값 누락을 못 잡았다. redact류는 클린 입력(오탐 체크) + dirty 입력(발화 체크) **두 방향 검증이 필수**. 한 쪽만 하면 반쪽.
- **새로 통한 것:** PyYAML 없는 환경 → 룰 파일 구조를 일부러 단순하게(키 + `- 한 줄 문자열`) 잡으면 미니 파서 20줄로 의존성 0. 외부 라이브러리 없을 때 "데이터 형식을 파서에 맞춰 단순화"하는 역방향 접근.
- **오탐 사례:** codename a/b/c/d 는 워크로그가 일상적으로 써서 전부 막으면 본문이 파괴됨 → "계정 a / account b" 매핑 패턴만 좁게 잡음. frontmatter 룰 우선순위: blacklist 는 `공개:` 값과 무관하게 무조건 redact, secret_keyword 는 `public` 이어도 경고만(이중 게이트).
