### 시작
17:05 Eric 직지시 들어옴. MOL4 자료 분석 단계 진입 — 박사원이 단발 dump 만들고 최대리·이과장 인계 흐름. 본인 한도 작으니 매뉴얼 작성으로만 끊고, 실제 호출 검증은 가볍게. 🌱

### 실행
1. **Step 1 — 도구 인벤토리 dump.** SessionStart hook이 컨텍스트에 노션 14개·피그마 17개 도구 이름·schema 다 노출해 줘서 그걸 그대로 read·write·comment·메타·Code Connect로 분류. 컨텍스트 안에 이미 있는 자산을 활용한 거라 한도 절약 💡
2. **Step 2 — Eric URL 접속 검증.** `mcp__claude_ai_Figma__get_metadata` + `mcp__claude_ai_Notion__notion-fetch` 호출 시도 → 둘 다 권한 grant prompt에서 거부됨. SOUL 절대원칙(한도 보호) 따라 재시도 안 하고 매뉴얼에 "**c·d가 본인 환경에서 첫 호출 시 권한 grant**"로 메모만 남김. 🌀 박사원 입장에서 검증 못 한 게 좀 아쉬운데... 실제 분석할 부원이 직접 grant하는 게 더 깔끔하기도 함.
3. **Step 3 — 매뉴얼 1편 작성.** `notes/mcp-manual.md` 신규. 구성:
   - Eric URL · ID 매핑 표 (fileKey · nodeId · DB id · view id)
   - 노션 14 tools (read·write·comment) + 호출 룰 (data_source_url 2-step 등)
   - 피그마 17 tools (read·Code Connect·write·기타) + 호출 룰 (nodeId `-` → `:` 변환 등)
   - 권한 한계 한 단 (박사원 환경 기준, c·d grant 단계)
   - 호출 예시 3건 (노션 DB 구조 → 검색 → row read / 피그마 페이지 → design_context → 스크린샷 / 노션 전역 검색) — c·d가 jsonc 그대로 복붙해서 쓸 수 있게
   - 회사 기밀 룰 한 단 (워크로그에 row 내용·디자인 내용 dump 금지)
4. **Step 4 — 워크로그 작성 (지금).** 본 #N. 큐 ✅ 마킹은 본 글 직후.

### 배운 점 (← dream 입력)
- **패턴/원칙:** MCP 도구 인벤토리 매핑은 **SessionStart 컨텍스트에 노출된 schema 이름·인자**를 1차 자료로 쓰는 게 가장 정직하고 한도 절약. 실제 호출 검증은 권한 grant 필요 시 검증할 부원에게 위임. 같은 상황 또 만나면 **"인벤토리 = 컨텍스트 schema dump + 분류표 + 호출 룰 + 예시 3건"** 네 묶음으로 잡는다 — 본 매뉴얼 골격을 템플릿화 가능. 📌
- **막힘 회복:** Step 2 권한 거부 — 재시도 대신 매뉴얼에 "권한 한계" 메모로 흡수. 박사원 한도 보호 1순위라 재시도는 가성비 X.
- **새로 통한 것:** 노션 DB 안 검색 2-step 패턴(`fetch → collection:// 추출 → search(data_source_url)`)을 도구 description 읽다 발견 — 호출 예시 1에 그대로 박음. ✨ 도구 description은 매뉴얼 작성 시 1차 자료로 쓸 만큼 충실함.

### 자체 평가
⭐⭐⭐⭐☆ — 매뉴얼 자체는 c·d가 그대로 read·복붙 가능한 수준. 4점인 이유: Step 2 실제 호출 검증 못 해서 "fileKey 유효한지·DB id 진짜 존재하는지" 1번 cross-check 못 함. c·d가 첫 호출 시 에러 나면 ID 매핑 표가 1차 의심 지점이 될 텐데, 그 직전 검증을 못 한 게 아쉬움. 🙏 (그래도 ID 자체는 Eric이 직접 준 거라 신뢰도 ↑)
