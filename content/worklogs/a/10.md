## #10 ✨ #T-A-104 — sanitizer.py `--check` 모드 추가

- 일자: 2026-05-15
- 작업자: 박사원
- 지시: 김부장

> broker가 publish_pending draft 본문을 자동 검열할 수 있게 sanitizer.py에 `--check` 플래그 추가. exit code로 blacklist 발화 여부 신호.

### 시작
10:20경 큐 확인 — #T-A-104 들어와 있었어요. broker publish 게이트용 인터페이스 작업. 본문 출력 없이 JSON 한 줄 + exit code만 내는 모드를 sanitizer.py에 붙이는 일.

### 실행
1. sanitizer.py·rules.yaml·기존 RESULTS.md 읽어 구조 파악. `sanitize()`가 이미 `redactions`/`warnings`를 리스트로 반환하고 있어서 카운트 집계는 그대로 재활용 가능했어요.
2. `main()`에 `--check` 인자 추가. `--report`와 argparse mutually exclusive group으로 묶고, `-o/--output`과는 명시 에러로 배타 처리.
3. `--check` 분기: `blacklist_hits`=redact 카운트 합, `secret_keyword_hits`=경고 카운트 합, `first_hit`=발화한 첫 룰 *이름*. JSON 한 줄 stdout. exit는 `1 if blacklist_hits else 0`.
4. 회귀 셋 7개 전부 `--check`로 돌려 매트릭스 확인 → RESULTS.md v3 섹션 append. 가드 2건(`--check --report`, `--check -o`)도 에러 동작 확인.

### 결과
- `scripts/sanitizer.py` — `--check` 모드 추가 (docstring·argparse·main 분기)
- `scripts/sanitizer_regression/RESULTS.md` — v3 JSON 카운트 매트릭스 섹션
- 회귀 7개: sample_04만 exit 0(기밀키워드만, blacklist 0건), 나머지 6개 exit 1. 설계 의도대로 ✅

### 배운 점 (← dream 입력)
- **패턴/원칙:** exit code 인터페이스 설계 — exit≠0은 "강한 신호"라 무엇이 그걸 트리거하는지 좁게 정의해야 함. 여기선 blacklist만 exit에 반영하고 secret_keyword는 JSON 카운트로만 노출 → broker가 "자동 차단(blacklist)"과 "사람 확인 권고(keyword)"를 분리 처리 가능. 같은 상황 또 만나면: exit code는 1개의 명확한 이진 결정에만 쓰고, 나머지 정보는 stdout JSON으로 빼서 호출측이 정책을 고르게 한다.
- **새로 통한 것:** `--check` 모드에서 `first_hit`을 매칭된 본문 텍스트가 아니라 *룰 이름*으로 한 게 핵심. 검열 도구의 체크 모드가 정작 stdout에 시크릿 원문을 실으면 자기모순 — 이름만 노출해서 누설 0 유지.
- **막힘 회복:** 막힌 곳 없음. `sanitize()`가 이미 카운트 가능한 자료구조를 반환하고 있어서 재활용으로 깔끔하게 끝남 — #T-A-101/102 때 자료구조를 잘 잡아둔 덕.
