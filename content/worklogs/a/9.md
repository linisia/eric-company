## #9 🛠️ #T-A-102 — Sanitizer 회귀 테스트 셋 확장

- 일자: 2026-05-14
- 작업자: 박사원
- 지시: 김부장 위임 (#T-A-102)

> "sanitizer.py 변종 dirty 샘플 7개 추가해 회귀 테스트 셋 보강. 발견한 누락·오탐은 yaml 갱신 후 결재요청."

### 시작
18:07 큐의 #T-A-102. 노는 시간 활용 지시. #8(#T-A-101)에서 만든 sanitizer 를 변종 7종으로 두들겨 보는 회귀 셋 작업.

### 실행
1. `scripts/sanitizer_regression/` 만들고 변종 7종 작성 — 코드블록 안 토큰 / 이메일 / 절대경로 / 기밀키워드만(public 게이트) / 절반깨끗절반위험 / codename 변종 / URL 쿼리스트링 토큰. 각 샘플에 "살아야 하는 것"도 일부러 심어 오탐 체크용으로 씀.
2. 7개 전부 sanitizer.py 통과 → 1차 결과에서 **누락 4건 + 오탐 1건** 발견.
   - 누락: ① `tg_bot_var` 가 변수명만 먹고 `=값` 누설 (#T-A-101 api_key_var 버그와 똑같은 패턴!) ② `tg_bot_token` 앞 `\b` 가 `bot8123...` URL 안에서 경계 못 만듦 ③ GitHub `ghp_` 토큰 룰 부재 ④ codename `account-a` 하이픈형 / `a 계정` 어순역전 미매칭.
   - 오탐: `codename a/b/c/d` 일반 나열을 매핑 누설로 오인.
3. **명백·기확립 패턴 3건만 yaml 직접 갱신** — tg_bot_var 에 `=값` 캡처 추가, tg_bot_token `\b`→`(?<!\d)`, github_token 룰 신설. 재실행 → sample_01·07 전부 발화 확인 ✅
4. **판단성 3건(abs_path 룰순서 꼬리누설 / codename 나열 오탐 / codename 룰 확장)은 박사원 단독 보류** — RESULTS.md 에 🔔 결재요청 섹션으로 정리. SOUL대로 결정적 판단은 부장님께.
5. `RESULTS.md` 작성 — 변종별 발화·오탐·조치 표 + 상세.

### 결과
- `scripts/sanitizer_regression/sample_01..07.md` — 변종 7종 ✅
- `scripts/sanitizer_regression/RESULTS.md` — 결과 매니페스트 + 결재요청 3건 ✅
- `scripts/sanitizer_rules.yaml` — 룰 3건 갱신 (tg_bot_var·tg_bot_token·github_token 신설) ✅

### 배운 점 (← dream 입력)
- **패턴/원칙:** 회귀 셋은 "발화돼야 하는 것"만 넣지 말고 **"살아남아야 하는 것(오탐 미끼)"을 같은 샘플에 섞어** 넣어야 진짜 회귀 셋이다. sample_05·06 의 깨끗 절반이 오탐 1건을 잡아냈다. 다음에 테스트 셋 짤 일 있으면 처음부터 positive/negative 케이스를 한 파일에 짝지어 둔다.
- **막힘 회복:** `tg_bot_var` 값 누설은 #T-A-101 워크로그에 적어둔 "변수명만 먹는 좁은 룰" 교훈 그대로였다. **과거 워크로그의 배운 점이 이번 누락 진단을 1분 만에 끝내줬다** — 학습일지가 실제로 작동함. 같은 버그 클래스는 룰 패밀리 전체에 한 번에 적용해야 한다(api_key_var 만 고치고 tg_bot_var 를 빠뜨린 게 이번 누락의 원인).
- **새로 통한 것:** 정규식 `\b` 는 URL 처럼 word-char 가 빽빽한 문맥에서 경계가 안 생긴다. 토큰이 다른 식별자에 붙어 사는 케이스는 `\b` 대신 `(?<!\d)` 같은 lookbehind 로 "바로 앞 문자 종류"를 직접 지정하는 게 안전.
- **오탐 사례:** 룰 순차 치환이 서로의 입력을 깨먹는 케이스 발견(email 룰이 경로 중간 이메일을 먼저 치환 → 삽입된 `→ [REDACTED]` 의 공백 때문에 abs_path 룰이 꼬리를 놓침). #T-A-101 의 "넓은 룰 먼저" 교훈만으로는 안 풀리는 상호작용 — 김부장 결재 안건으로 넘김.
