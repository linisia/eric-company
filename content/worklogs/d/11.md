## #11 🛠️ T-D-106 사용량 표기 룰 일괄 패치

- 일자: 2026-05-15
- 작업자: 이과장
- 지시: 김부장 (Eric 결재 통과)

> "본인이 결재요청한 사용량 표기 룰 3건을 시스템 전체 양식에 일괄 반영."

### 시작
10:15, #9에서 내가 올렸던 결재안이 Eric 통과로 돌아옴. 4건 패치 — worklog 템플릿·usage README·soul 4종·usage-push.sh PATH 픽스. hook이 덮어쓰는 영역 vs static 영역 구분이 이번 작업의 진짜 축.

### 실행
1. `scripts/usage-push.sh` — `export PATH="$HOME/.npm-global/bin:/opt/homebrew/bin:/usr/local/bin:$PATH"` 추가. 절대경로 박지 않은 이유는 brew 환경(`/opt/homebrew/bin`)도 같이 잡아둬야 다른 부원 머신·미래 마이그레이션 시 안 깨짐.
2. `templates/worklog.md` — 핵심 원칙에 4번 항목 append (`$X.XX` 단독 금지 + 통일 형식). 양식 사용 가이드가 아니라 **원칙** 섹션에 박은 이유: 헤더 형식 보존(#3)이랑 동급 강제력 원해서.
3. `soul/{b,c,d}.md` — 임계점 "5h" → "5h 슬롯" / "5h 임계(72%)" → "5h 슬롯 임계(72%)". 박사원 `a.md`는 Sonnet Pro 구조라 5h 슬롯 표기 자체가 원래 없음(주간 한도 단일). 부장님 지시 "a,b,c,d"였지만 a는 통일 대상 외라 판단 — 손 안 댐.
4. `usage/README.md` 신규 — schema 주석 + 표기 룰 + 임계 기준 3섹션. json 본문은 hook이 덮어쓰니 README에 가이드만(지시 그대로).
5. dry-run — `usage-push.sh d $HOME/.claude-account-d` 직접 호출. **`note: "ccusage not installed"` 키 사라짐 확인** = PATH 패치 정상 동작. `last_updated` 갱신도 OK.

### 결과
- `scripts/usage-push.sh` PATH export 추가 ✅
- `templates/worklog.md` 원칙 #4 추가 ✅
- `usage/README.md` 신규 ✅
- `soul/{b,c,d}.md` "슬롯" 단어 보강 ✅
- `soul/a.md` 통일 대상 외 판단 (역제안) ⚠️ — 부장님 확인 필요

### 배운 점 (← dream 입력)
- **패턴/원칙:** **hook이 덮어쓰는 영역(usage/*.json)에 가이드를 박을 땐 본문이 아니라 인접 README로 빼라.** 본문에 주석 박아봐야 다음 갱신에 날아감. static 영역(worklog 템플릿, soul, 스크립트)에는 직접 박아도 됨. 같은 상황 또 만나면 "이 파일이 다음 hook 사이클에 덮여 쓰이나"를 첫 질문으로 던지고 답에 따라 인플레이스 vs 외곽 가이드 선택.
- **역제안 누적:** 지시는 `soul/{a,b,c,d}.md` 4건이었는데, 박사원은 Sonnet Pro 구조라 5h 슬롯 표기 자체가 없어서 a만 통일 대상 외로 판단했다. 다음엔 패치 발주 받자마자 대상 파일 한 번씩 grep으로 훑어 "지시 범위 적합성"부터 검증하고 시작하자. 지금처럼 작업 후 회고에서 알리는 것보다 작업 전 한 줄 보고가 부장 입장에서 결재 사이클 짧음.
- **새로 통한 것:** `export PATH=...:$PATH` 한 줄로 hook 환경 PATH 버그 즉시 해소. 절대경로보다 PATH 보강이 이식성↑. brew 경로(`/opt/homebrew/bin`)도 같이 잡는 게 macOS 환경 표준.
- **막힘 회복:** 없음. spec·결재안 다 내 손으로 짜둔 거라 흐름 막힘 0.

### 자체 평가
⭐⭐⭐⭐⭐ — 작업 단순했지만 hook 영역/static 영역 구분이라는 메타 룰을 검증하면서 진행했고, 역제안(a 제외)도 작업 중 자기 판단으로 들어갔다. dry-run으로 PATH 패치 실증까지 한 게 완결적.
