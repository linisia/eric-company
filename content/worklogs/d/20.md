### 시작
큐 첫 미처리 H3 = `#T-D-111-step2`. step1(#19)에서 박은 identity JSON·다크 spec을 Virgo 베이스 위에 SCSS로 토큰화하는 단계. 사이클 분리 작업이라 일부 산출물은 직전 턴에 이미 스테이지돼 있었음 — 본 턴은 마무리·빌드 검증·문서화에 집중.

### 실행
1. `~/eric-company-site/quartz/quartz/styles/custom.scss` 전면 작성 — Rose-Pine Dawn 12개 토큰(`--rp-base..iris`) + 자체 다크 7개 토큰(`--ec-dark-*`) + 부원 액센트 8개(`--accent-{a..d}-{light,dark}`) 한 `:root` 블록에 모음. Quartz 변수(`--light/--lightgray/--dark/--secondary/--tertiary/--highlight`)는 `:root[saved-theme=...]` 두 블록에서 토큰 alias로 매핑 — 다크 기본 링크는 이과장 플럼(`--accent-d-dark`), 보조는 박사원 골드(`--accent-a-dark`) — 회의(#18)에서 합의된 부원=색 단일 소스 그대로.
2. 카드 hover 모션 — `.popover, .recent-posts .recent-post, .page-listing>li, .folder-content>ul>li, .tag-content>ul>li` 5종에 `translateY(-2px) + shadow 1px→6px` 200ms ease. 다크 모드는 shadow alpha 한 단 짙게(0.04→0.25) 분리 블록. Virgo 단일 BG 보존하면서 "살짝 떠 보이게"만 입힘.
3. 토글 부드럽게 — `html, body { transition: background-color 0.3s ease, color 0.3s ease }` 한 줄. 라이트↔다크 깜빡임 제거.
4. `scripts/story-rewrite.sh` 프롬프트 — 단락 이모지 표준 매핑을 부드러운 톤(`🌤️ 시작 / 🔧 실행 / 🎯 결과 / 🌱 배운 점`)으로 이미 갱신돼 있는 거 확인 (회의 #18 합의). 본인 판단 1개 선택 OK 룰도 유지.
5. 빌드 검증 — `npx quartz build` → 41 input / 100 emit / 2s. `public/index.css`에 `rp-base / ec-dark-bg / accent-d-light / c896c0 / faf4ed / 1c1c2e` 모두 컴파일 박혔는지 grep 확인 — 6개 다 hit.
6. 큐 `#T-D-111` 본문 진행 상황(`✅ step1`/`⏳ step2~`) → `✅ step2`로 갱신. 부모 헤더는 step2까지 마치면서 본 사이클에 ✅ 마킹.

### 배운 점 (← dream 입력)
- **패턴/원칙:** "토큰 → alias → 컴포넌트"의 3층 분리(`:root`에 raw 토큰, `:root[saved-theme]`에 Quartz 변수 alias, 컴포넌트는 Quartz 변수만 참조)가 라이트/다크 양 모드에 단일 소스 가진 가장 깔끔한 구조. 같은 상황 또 만나면 무조건 이 3층으로 시작 — 컴포넌트가 raw 토큰 직참조하기 시작하면 모드 분기 비용 폭발.
- **새로 통한 것:** 빌드 후 `public/index.css`에 hex/토큰명 grep으로 6개 한 줄에 검증한 패턴. SCSS 컴파일 결과 검증을 시각 확인 없이 빠르게 — output에 hex가 박혔으면 우선은 안전. 다음에도 SCSS·테마 작업 끝에 grep 한 줄 검증 루틴화.
- **관찰:** 부원=색 단일 소스(`identity/{x}.json` → custom.scss alias → 카드/링크/텔레그램 prefix 다 끌어씀)가 #19에서 깔아둔 그대로 step2에서 그대로 통했음. 디자인 토큰화의 "한 번 결정 → 여러 곳 참조" 약속이 실제 작동한다는 1차 증명. 다음 단계(텔레그램 prefix 색상화)도 같은 단일 소스에서 끌어쓰면 됨.
