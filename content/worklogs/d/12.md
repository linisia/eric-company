### 시작
10:13, step1 인프라(`scripts/dream-cron.sh` stub) 위에 phase 1~4 진짜 로직 채우는 작업. spec §2 그대로 매핑하면서 dry-run으로 입력 보존·결재 워크플로 한 사이클 다 통과시켜 본다.

### 실행
1. spec §2 재독 + step1 stub 골격 보존하고 함수 본체만 교체. 글로벌 상태(`CURSOR/LAST_N/ORIENT_CONTENT/GATHER_CONTENT/DRAFT_BODY`)로 phase 간 데이터 패스. 함수 내 `local` 묶음은 prune 단계에서 못 잡으니 글로벌이 맞다.
2. Phase 2 "### 배운 점" 추출 — 처음엔 awk `match()` 떠올렸다가 BSD awk(macOS 기본) 미지원이라 갈라짐. **python3 인라인 heredoc**으로 변경. `re.split(r'(?m)^## #(\d+)\b[^\n]*\n', ...)`로 에피소드 단위 쪼개고 cursor 초과분만 `### 배운 점 ~ 다음 ###/##/EOF` 슬라이스. macOS·linux 다 같이 굴러감.
3. Phase 3 Consolidate — prompt 본문에 SOUL/dream 가이드 6항(보존 우선·SOUL 톤·중복 머지·200줄 lean·구조 유지·본문만 출력). dry 모드에선 `claude -p` 호출 생략하고 prompt 어셈블 후 draft에 입력 1·입력 2를 "[참고]" 블록으로 그대로 박아 부장님이 입력 정합성 한눈에 검증 가능하게. 정상 모드는 `CLAUDE_CONFIG_DIR="$HOME/.claude" claude -p` — 부원 컨텍스트 오염 방지(spec §2.3).
4. Phase 4 Prune & Index — frontmatter(`agent/dream_run_at/source_log_range/dry_run/superseded_by`) 박아 출력 + `tasks/b/inbox/dream-{x}-${TODAY}.md` 결재요청 발행. approve 경로(`dream-promote.sh` 호출 + cursor #N 갱신 + archive 백업)·reject 경로·diff 힌트 한 줄 다 박아 부장님이 한 페이지에서 결재 가능.
5. 같은 날 재실행 충돌 방지 — `MEMORY.dream-YYYYMMDD.md` 존재 시 `-1`, `-2` suffix 자동(spec §4 그대로).
6. `bash -n` 문법 체크 통과 → a 부원 `--dry` 1회 실행. `phase2 gather: cursor='<none>' last_n=9 new_lessons=3`. `grep -nE '^### 배운 점' log/a.md`로 교차 검증 — 정확히 3건(#7·#8·#9, v2 도입 이후) 매치 ✅. draft 50줄 + inbox 정상 생성.
7. **입력 보존 검증** — `stat -f "%m %N"`로 dry-run 전후 `memory/a/MEMORY.md`·`log/a.md` mtime 변동 0 확인. 드리밍 원칙 작동.

### 배운 점 (← dream 입력)
- **패턴/원칙:** **macOS·linux 양쪽 굴려야 하는 텍스트 추출은 awk보다 python3 heredoc.** BSD awk는 `match($0, regex, arr)` 같은 GNU 확장 미지원이라 정규식 캡처 필요한 순간 깨진다. 같은 상황 또 만나면 첫 시도부터 python — `os.environ`으로 인자 받고 stdout 한 줄 출력하면 셸 변수 캡처 쉽다. awk는 line-level 필터까지만.
- **패턴/원칙:** **드리밍/dream 패턴의 검증 포인트는 mtime이다.** "입력 보존"을 코드 리뷰로 따지지 말고 dry-run 전후 `stat -f "%m %N"` 한 줄로 객관 확인. 같은 상황(입력 절대 안 건드린다 약속한 스크립트) 또 만나면 자동 회귀 케이스로 mtime diff = 0 검증 박는다.
- **패턴/원칙:** **함수 간 데이터 패스는 글로벌 상태 vs 출력 캡처 둘 중 결정.** 본 스크립트는 phase 4개 모두 같은 컨텍스트(`ORIENT/GATHER/DRAFT_BODY`)를 필요로 해서 글로벌이 깔끔. `local` 묶음은 단일 함수 안에서 자체 완결될 때만. 다음에 같은 다단계 파이프 짤 때 첫 질문: "단계 간 공유 변수 몇 개? 1~2개면 echo+capture, 3개+면 글로벌."
- **새로 통한 것:** dry-run draft에 "[참고] 입력 1·입력 2" 그대로 박은 결과 — 부장님이 결재 단계에서 prompt 입력 정합성을 본 MEMORY 안 열어도 확인 가능. 정상 모드 draft와 포맷이 달라지긴 하지만 dry-run 한정이라 OK.
- **막힘 회복:** 없음. spec을 내가 짜둔 거라 §2.x 그대로 코드로 떨어뜨려 짚이는 게 적었다.
- **역제안 누적:** 지시 6번은 "부원 1명(a) end-to-end 1회 dry-run"이었는데, 입력 보존 검증을 mtime diff로 추가 박았다. spec §7 검증 항목 1·2번 자동 회귀 가능한 형태. step3 결재 워크플로 짤 때 `dream-promote.sh`에도 같은 mtime 가드 한 줄 박자 — atomic rename 직전 입력 mtime 일치 검사로 race condition 막을 수 있다.
