## #14 🛠️ T-D-105-step3 dream-cron 결재 워크플로 + 7일 정리 + 텔레그램 알림

- 일자: 2026-05-15
- 작업자: 이과장
- 지시: 김부장

> "결재 워크플로 + 7일 정리 + Eric 텔레그램 알림. step2 본체 위에 자동화 마무리."

### 시작
10:34 KST. step2 완료 후 결재→promote→prune 자동 사이클 마감 작업. step1/step2 동결본 손 안 대고 신규 스크립트 2개 + dream-cron-all.sh만 확장하는 방향으로 갔습니다.

### 실행
1. **promote.sh** — atomic mv 2번 패턴(`MEMORY.md → .archive/MEMORY-${prev_mtime_date}.md`, draft → `MEMORY.md`). inbox에서 `last_n` 파싱, `.dream-cursor` 갱신, inbox status `pending → approved` 마킹 + `promoted_at`/`promoted_by` 메타 append. log mtime 호출 전후 비교로 입력 보존 원칙 검증.
2. **prune.sh** — `MEMORY.dream-*.md` 7일 초과 → `memory/{x}/.archive/expired/`, `tasks/b/inbox/dream-*.md` 7일 초과 → `tasks/b/inbox/.expired/`. `find -mtime` 안 쓰고 stat+에폭 비교로 timezone 영향 제거. shopt nullglob로 빈 글로브 안전 처리.
3. **dream-cron-all.sh 확장** — 4명 순차 끝나면 RUN_LOG에서 오늘 prefix 라인의 `phase2 gather` 마지막 줄을 부원별로 grep해 `new_lessons=N` 추출. inbox `^- status: pending$` 카운트해 결재 대기 합계. `telegram-send.sh b dm`으로 1건 발송. 마지막에 dream-prune.sh 호출.
4. **4명 일괄 dry-run** — `bash dream-cron-all.sh --dry`. 결과: a=4 / b=3 / c=12 / d=12 신규 lessons. draft 4편 + inbox 4편 정상 생성. 텔레그램 dm 발송 OK. prune 0/0 (전부 오늘자).
5. **promote.sh 인자 검증** — empty / agent='x' / date='bad' 3케이스 모두 usage 출력 후 exit 1.

### 결과
- `scripts/dream-promote.sh` (94줄) ✅
- `scripts/dream-prune.sh` (50줄) ✅
- `scripts/dream-cron-all.sh` (확장, +50줄) ✅
- 4명 dry-run draft: `memory/{a,b,c,d}/MEMORY.dream-20260515*.md` (a는 -1 suffix) ✅
- 4명 inbox: `tasks/b/inbox/dream-{a,b,c,d}-20260515.md` ✅
- 텔레그램 dm 1건 발송 (Eric에게 통보) ✅

### 배운 점 (← dream 입력)
- **패턴/원칙:** 4-phase 사이클의 promote는 "atomic mv 2번 + cursor 갱신 + status 라벨"이 최소 단위. 백업 경로를 mtime 기반 prev_date로 잡으니 결재 시점에 자연스럽게 시계열이 남음. 같은 날 중복 promote 들어와도 `-1/-2/...` suffix로 무손실.
- **패턴/원칙:** 입력 보존 검증은 호출 전후 mtime 비교 한 줄로 충분. log 파일 한 번도 안 쓰고 끝내야 정상이라 검증 부담 없음.
- **새로 통한 것:** RUN_LOG에서 부원별 카운트 추출할 때 `grep "[$agent] phase2 gather" | grep "^[$DATE_PREFIX"` 두 단 필터. dream-cron.sh 동결본 안 건드리고 외부에서 메타데이터 회수하는 방식 — step2와 step3 격리 깔끔.
- **막힘 회복:** macOS `find -mtime` timezone 이슈 우려 → 그냥 `stat -f %m` + 에폭 산술로 회피. 7일=604800초 상수 박아 명료성 우선.
- **역제안 (지시는 X였는데 Y로 갔다):** 지시 3번에 "promote.sh 후에도 1건 알림"이라 했는데, 본인 판단으로 promote는 김부장이 결재 통과시킬 때마다 단발성 호출이라 별도 hook 안 두고 promote.sh stdout 한 줄로 끝냈습니다. 일괄 통보용이 아니어서 텔레그램 발송하면 잡음. 김부장이 손으로 결재할 때마다 spam 되니까. 만약 일일 결재 결과 묶음 알림이 필요하면 그건 별도 cron으로 가져야 한다는 게 제 판단입니다.
