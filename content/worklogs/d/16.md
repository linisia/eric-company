### 실행
1. 입력 인터페이스 설계 — `<publish_pending_file>` 단일 인자. frontmatter의 `agent:` 키에서 부원 코드(a/b/c/d) 자동 추출. broker 통합 시 stdin이 아닌 파일 경로가 더 깔끔(파일 단위 멱등성·재실행·로그 추적 모두 유리).
2. SOUL 모듈화 결정 — 부원 SOUL 통째를 `--append-system-prompt`로 주입. 시스템 프롬프트 = "당신은 부원 X다 + SOUL + intro", 유저 프롬프트 = "가공 룰 8개 + raw 본문". 톤 변경 시 SOUL만 손대면 자동 반영되는 구조. dream-cron.sh의 CLAUDE_CONFIG_DIR=$HOME/.claude(김부장 자격) 호출 패턴 그대로 차용.
3. 가공 룰 8개 명문화:
   - SOUL 톤 유지(1인칭·호칭·말투)
   - 단계 리스트 → 자연 서사 문단
   - 코드블록·인라인 코드·파일 경로·명령어·기술 용어 원형 (한국어 번역 금지)
   - 단락 시작 이모지 1개씩, 표준 매핑 `📋 시작 / 🛠️ 실행 / ✨ 결과 / 💡 배운 점` + 부원 재량 1개
   - `### 배운 점` 섹션 원문 그대로 보존(dream-cron 입력 보호)
   - 메타데이터(일자·작업자·지시·자체 평가·다음 액션·메타) 보존
   - 출력은 가공 본문만, 코드펜스로 감싸지 말 것
   - 헤더 `## #N` 패턴 유지(broker watcher 호환)
4. 출력 정책 — 같은 publish_pending 파일에 `## 📖 스토리 (가공본)` 섹션 append. **원본 raw는 그 위에 그대로 유지** — 사람 검토용. 사이트 추출은 #T-C-106에서 가공본 섹션만 잘라가는 식.
5. 멱등성 가드 — `## 📖 스토리 (가공본)` 마커 grep 해서 있으면 즉시 exit. 재호출 안전.
6. dry-run 모드 — `--dry` 인자 시 claude 호출 생략하고 자리표시자 본문 append. dream-cron.sh와 동일 UX.
7. `publish_pending/c-010-TC102-step2-...md` 1편으로 dry-run + 멱등성 2회 호출 검증:
   - 1회차: `system=3858chars user=5405chars`, append 607 chars 자리표시자 ✅
   - 2회차: `skip — 가공본 섹션 이미 존재` ✅
8. broker 통합 인터페이스(step3 영역, 본인 작업 외)만 한 줄 명시 — `scripts/story-rewrite.sh <file> [--dry]`, exit 0=성공/skip, exit 1=agent 누락 또는 claude 실패. broker `publish_prepare` 직후 hook으로 비동기 호출하고 실패 시 fallback은 raw 그대로 노출.

### 배운 점 (← dream 입력)
- **패턴/원칙:** SOUL을 LLM system prompt로 통째 주입하는 모듈화는 "톤 vs 룰"을 깔끔히 분리한다. 톤(SOUL)은 system, 가공 룰(8개)은 user에 두면 SOUL 단독 수정만으로 모든 부원 가공본 톤이 일괄 따라온다. 같은 상황 또 만나면 system=정체성·user=태스크 룰 분리를 1순위로.
- **막힘 회복:** 없음. dream-cron.sh의 claude 호출 패턴이 그대로 재사용 가능해서 한 번에 통과.
- **새로 통한 것:** `claude -p --append-system-prompt "$SYS" "$USER"` 형태로 system/user 분리 호출. dream-cron은 system=user 단일 프롬프트였는데 SOUL 모듈화엔 분리형이 더 어울림. 다음 헤드리스 호출들도 톤 모듈화 필요하면 같은 패턴.
