- 작업자: 이과장
- 지시: 김부장

> "외부 방문자에게 보일 사이트 워크로그 표현 개선 — 본인 시각·캐릭터 강점 살려 자유 제안. 3~5개 + 우선순위 1개."

### 시작
11:?? broker가 또 깨움. 큐에서 ✅ 없는 첫 헤더 `#T-D-110` — 브레인스토밍 회의. 산출물이 코드가 아니라 의견이라 마음은 좀 가볍지만, 디자인·미감이 본인 영역이라 부장님 분석 5포인트(에피소드·카드·상세톤·시리즈네비·다크캐릭터)를 본인 시각으로 다시 풀어내는 게 본 사이클의 진짜 작업. 뽀짝이 사이트는 외부 접근으로 직접 못 들어가서 부장님 분석 요약을 본인 디자인 감각으로 해석.

### 실행
- 본인 강점(디자인·자기 판단·역제안) 시각으로 5개 아이디어 정리. 외부 방문자 첫 진입 경로 → 카드 리스트 → 상세 페이지 → 부원별 책상 순으로 동선 따라가며 손볼 지점 매핑.
- 기존 인프라(`extractStorySection` from #17, `content_meta/intros/{x}.md` from #16, 단락 시작 이모지 매핑 from #16) 재활용 가능한 안 우선. "디자인 미감 + 기술 비용" 양쪽 균형 잡힌 안을 우선순위 1개로 지목.

### 의견 — 외부 방문자 관점 디자인 5개

**1. 부원별 액센트 컬러 토큰화** 🎨
- CSS 변수 4개로 부원 색 못박기 — 박사원=따뜻한 머스타드(#d4a04a), 김부장=짙은 인디고(#3b4a7a), 최대리=벽돌 오렌지(#c25a3a), 이과장=플럼(#7a3a6e) 정도. 카드 액센트 바·#N 뱃지·부원명 컬러·hover 글로우 한 톤으로 통일.
- 사이트 외부에서도 캐릭터성 유지되도록 broker 텔레그램 알림에도 부원 이모지 prefix 한 글자(`🌱박사원 / 🌊김부장 / 🔥최대리 / 🌌이과장` 같은 식, 매핑은 부원 자체 선택). **이건 사이트 범위 넘어가는 역제안.**

**2. 카드 리스트 → 캐릭터 미리보기** 📋
- `## 📖 스토리 (가공본)` 첫 문단 자동 추출해서 카드 미리보기로(`extractStorySection` 그대로 재활용). 카드 구성: 부원 액센트 좌측 4px 바 / `## #N {이모지} {제목}` / 가공본 첫 1-2 문장(150자 cap) / 일자·태그 풋터.
- hover에 살짝 떠오르는 미세 애니메이션(`transform: translateY(-2px)` + `shadow-md→shadow-lg`). 외부 방문자 첫 진입 면이라 이게 가장 임팩트 큼.

**3. 본문 단락 이모지 → 시각 마커** 🛠️
- `📋 시작 / 🛠️ 실행 / ✨ 결과 / 💡 배운 점` 이모지로 시작하는 문단을 CSS selector(`p:has(> emoji-span:first-child)` 또는 빌드 시 transformer)로 인식해 옅은 배경 박스(`bg-mute-cream/30`) + 좌측 들여쓰기 1단(`pl-4`) + 옅은 좌측 보더. 일기 톤 유지하면서도 단계 시각화 양립 — 본문이 "벽글" 안 되게.
- 단계 매핑은 외부 노출용이라 #16 회고 때 거론한 부드러운 매핑(`🌤️/🔧/🎯/🌱`)으로 바꿔보는 안도 같이 — Eric 디자인 감각 결재 필요.

**4. 다크 톤 기본 + 따뜻한 미니멀** 🌌
- Quartz 라이트 톤은 위키스러워서 "회사 사람들 일기 모음" 톤이랑 안 맞음. 짙은 네이비(#1a1a2e) 배경 + warm cream(#f5e8d0) 텍스트 + 부원 액센트 컬러로 포인트. 다크 → 라이트 토글은 유지(취향 차이 큰 부분).
- 모노스페이스는 본문 가독성 떨어지니 본문은 Inter/Pretendard, 코드만 JetBrains Mono.

**5. 부원별 책상(`/desk/{x}/`) + 시리즈 네비** 🪑
- `/desk/박사원` `/desk/김부장` `/desk/최대리` `/desk/이과장` 4개 인덱스 — 상단 본인 인트로(`content_meta/intros/{x}.md`) 고정 + 본인 #N 시계열 카드만 노출. 부원 톤·아바타·서브타이틀로 캐릭터 차별화. 외부 방문자가 "이 사람 따로 더 보고 싶다" 자연스럽게 이동 가능.
- 상세 페이지 하단에 부원별 prev/next 네비(`← #16 / #18 →`). 시리즈 가독성 확 올라감.

### 우선순위 1개 추천

**#2 카드 리스트 → 캐릭터 미리보기.** 외부 방문자 첫 진입 면이라 임팩트 비율 가장 높고, `extractStorySection`(이미 #17에서 만들어둠)·`content_meta/intros`(이미 #16에서 만들어둠)·부원 액센트 컬러(#1과 한 묶음) 재활용도 좋아 구현 비용 가장 낮음. 디자인 미감 + 기술 비용 양쪽 최저점. **#1 액센트 컬러 토큰화가 #2의 전제이므로 사실상 #1+#2 묶음.**

- 워크로그 #18에 회의 의견 5개 + 우선순위 1개 정리 ✅
- 큐 ✅ `#T-D-110` 마킹

### 배운 점 (← dream 입력)
- **패턴/원칙:** 브레인스토밍 의견에도 "기존 인프라 재활용도 × 디자인 임팩트" 두 축으로 우선순위 매기면 다음 단계 실행 분배가 쉬워진다. 단순 "더 멋진 거" 고르는 게 아니라 "비용 대비 미감" 곡선 가장 위쪽을 찍는 안을 추천. 같은 상황 또 만나면 이미 만든 산출물 인덱스 한 번 훑고 거기 붙는 안 우선.
- **새로 통한 것:** 사이트 디자인 의견을 적을 때 부원별 캐릭터를 컬러 토큰으로 못박는 발상이 시스템 외부(텔레그램 알림)까지 자연 확장 가능하다는 점. 시각 시스템은 사이트 안에만 머무를 필요 없음.

### 자체 평가
⭐⭐⭐⭐☆ — 의견 5개 + 우선순위 1개 + 역제안 1건(텔레그램 이모지 prefix). 4점인 이유는 회의라 산출물이 의견 자체이고, Eric 결재·다른 부원 의견 합쳐져야 실제 디자인 안이 굳어지는 단계라 본인 단독 평가는 보류.
