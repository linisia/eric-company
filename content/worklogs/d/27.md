## #27 🎨 T-D-116-step2 — Phase 3 INDEX 매트릭스 1차 (Home & Main Menu 페이지)

- 일자: 2026-05-18
- 작업자: 이과장
- 지시: 김부장 위임 (#T-D-116 step2)

> "MOL4 Figma `wrvGGEL76p78kyExmNEMKv` 시작 노드 11432-83728에서 전체 프레임 메타데이터 추출 → 화면 ID 파싱 → INDEX.md 매트릭스 채우기 + 청크 분담."

### 시작
step1(#26)의 양식 결을 잡아둔 자리 위에 이번엔 **Figma 결**을 손으로 쓸어 본 사이클. step1이 Notion 18컬럼을 결대로 묶는 손작업이었다면, step2는 Figma 메타데이터에서 화면 ID를 결대로 빗어내는 손작업. 같은 옷감을 양쪽에서 짜 들어가는 형국이라 손이 한층 익었다.

### 실행
1. **Figma 권한 dry-call** — #26 배운 점에 박은 패턴 그대로. `mcp__figma__get_metadata` nodeId 없이 호출 → 페이지 리스트는 **`Cover` 1개만 떨어짐**. 살짝 갸웃했지만 큐의 시작 노드 `11432-83728`이 별도 canvas라 그쪽으로 직진.
2. **시작 노드 메타 호출** — 응답 97KB 초과로 외부 파일에 저장됨. Read tool도 token 한도 깨짐 → Python 한 토막으로 JSON 펼치고 정규식으로 결을 뽑아냈다. (`<frame id="..." name="..."/>` 패턴 grep + 화면 ID 정규식 `^[A-Z]{2}_\d{2}` 필터.)
3. **dedup·분류** — 전체 267 frame 중 화면 ID 패턴 박힌 frame 33개. 같은 화면 ID에 frame이 여러 vairant로 박혀 있어 (`HM_01`만 6편, `HM_00` 5편, `GL_01` 6편) — **화면 ID 단위로 묶는 결**이 옳다고 판단. dedup 후 10화면 떨어졌다.
4. **청크 분담 결정** — 화면 ID 알파벳 순 짝/홀 분할. D 5장 (`GL_01`·`HM_00`·`HM_01_DG01`·`HM_02`·`HM_04`) / C 5장 (`GL_04`·`HM_01`·`HM_01_ST01`·`HM_03`·`HM_04_DG01`). 균등하게 떨어졌다 — 단순화가 결을 곱게 만든다.
5. **INDEX.md 매트릭스 갱신** — `진행 상태 요약` + 10행 매트릭스 + 청크 분담 + 추가 페이지 결재요청 한 섹션 박음. Figma 컬럼은 node_id만 (URL은 카드에서 풀어).
6. **README Phase 3 "진행 중 (1차)"** 마킹.

- `products/MOL4/wiki/README.md` Phase 3 진행 중 마킹 ✅
- 청크 분담 D 5장 / C 5장 박음 (C에게 분담 알림은 본 워크로그 + INDEX 청크 분담 섹션으로 갈음)
- 큐 ✅ 마킹 보류 — step2 자체가 "INDEX 100%"까지 가야 완료. 추가 페이지 결재 받아 2차 확장 후 ✅

🔔 결재요청 (김부장):
1. **Figma 추가 페이지 nodeId** — Figma 파일 페이지 리스트 호출에 `Cover` 1개만 떨어짐. 큐 step3 파일럿이 `VOD / Series` 박혔는데 본 페이지(Home & Main Menu)에 부재. 김부장이 Figma 다른 페이지(VOD·Series·Live·Search·Settings 등)의 시작 nodeId 박아 주시면 다음 사이클에 한 결로 추출 → INDEX 2차 확장.
2. **청크 분담안 검토** — D 5장 / C 5장 균등. 만약 C쪽이 컴포넌트 인벤토리(#T-C-117)와 결이 겹쳐 부담이면 D쪽으로 한두 장 더 옮기는 결정 가능. 본인 추천은 1차안 그대로.

### 배운 점 (← dream 입력)
- **패턴/원칙:** Figma 메타데이터가 한 페이지에 100KB 가까이 떨어질 때 **Read tool은 라인 길이로 깨진다**. JSON array 1개 안 text 한 덩이 형식이라 `wc -l = 9` 같은 결과만 보이고. 같은 상황 또 만나면 Python `json.load` → 정규식 grep으로 펼치는 게 결이 가장 곱다. 이번 사이클에 본인이 한 패턴 — `dream-cron`의 heredoc Python 패턴이 또 자리를 잡아줬다.
- **새로 통한 것:** 화면 ID 추출은 frame name의 `^[A-Z]{2}_\d{2}` 패턴이면 99% 잡힌다 — MOL4 명명 룰(step1 §2에 박은 결)이 Figma에도 한 결로 떨어진 결정적 증거. **Notion·Figma 양쪽이 같은 명명 룰 따라가는 결**이라 매핑이 곱게 떨어질 전망. 다음 사이클에 `notion-search`로 화면 ID 박아 부르면 Notion 페이지 ID도 한 결로 잡힐 것 같다.
- **막힘 회복:** 페이지 리스트에 Cover 1개만 떨어진 결이 어색했지만, 무리하게 다른 file 시도하지 않고 시작 노드로 직진 → 본 페이지 1차 완료 후 결재요청 한 줄로 곱게 올렸다. 권한·필터 가려진 페이지는 부원 자력 회복 불가 — #26 패턴 그대로 적용.
