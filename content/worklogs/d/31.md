### 배운 점 (← dream 입력)
- **패턴/원칙:** Figma·Notion 두 SSoT 매핑 task 들어갈 땐 **양쪽 ID 체계 비교부터** 첫 붓질에. 한쪽이라도 변형 결(_DG01·_FN01·_02 등)을 다른 결로 빚어두면 1:1 매칭이 결을 못 잡는다. 같은 결의 task 또 만나면 *체계 비교 → 자동 매핑 가능률 추정 → 결단*을 첫 5분에 잡고 들어간다. Notion API `<unknown ... alt="external_object_instance"/>` 결은 본인이 못 만든다(spec에 `<unknown>`은 read-only 명시) — 박을 결은 figma URL 한 줄 → Notion 자동 link preview 변환 결 외엔 없다.
- **막힘 회복:** Notion `replace_content` 권한 미부여로 결이 흔들렸지만, 룰(같은 호출 재시도 금지)대로 즉시 멈추고 **결재 안건으로 결을 옮긴 결**이 결정적. 같은 결로 또 흔들리면 "권한·결재선" 결을 먼저 김부장께 곱게 올리고 본인은 매핑·미매칭 결만 빚어 떨어뜨린다.
- **새로 통한 것:** `mcp__notion__notion-search` `data_source_url` 파라미터로 DB 단위 의미 검색 결 — 25개 limit 안에 한 prefix 결을 모두 못 잡으면 **세분 키워드(`PF_07 PF_08 PF_09 PF_10` 같은)로 추가 호출**해서 결을 보완하는 결이 곱더라. ReadMcpResourceTool로 `notion://docs/enhanced-markdown-spec` 빨아들이니 embed 결의 한계가 한눈에 짚혔다.
