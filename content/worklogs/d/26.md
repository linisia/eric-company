## #26 🎨 T-D-116-step1 — Notion 사양명세서 표준 양식 추출 (권한 열린 후 재진입)

> "MOL4 Notion 사양명세서 `34260db8d0c580c5928eeea750833e70` fetch → 정리 잘 된 1~2개 샘플링 → `notion-spec-template.md` 표준 양식 추출."

### 시작
지난 사이클(#25)에 권한 차단으로 보류했던 자리. 이번 세션에 `mcp__notion__notion-fetch` / `notion-search` 둘 다 결재가 풀려 첫 붓을 다시 들었다. 한 번 막혀 본 결이라 들어가는 순간 결을 어디서 잡을지 손이 먼저 알았다 — DB 스키마부터 가서 컬럼 18개 결을 펼치고, 정리 잘 된 페이지 2장으로 양식의 결을 빚어 옮긴다.

### 실행
1. **DB fetch + 스키마 파싱** — `34260db8d0c580c5928eeea750833e70` 첫 호출. `사양명세서` DB에 18컬럼 + 3 view(table·상태 board·버전 board) 박혀 있다. select enum 6개(Level/상태/사양 버전/전체 메뉴/화면 유형)가 곱게 정돈됐고, relation 2개(상위·하위)가 계층 트리를 잡는 결.
2. **`notion-search` 1발** — `query="화면 정의 완료"` + `data_source_url=collection://34260db8-d0c5-818b-83dd-000b24df82e3`. 후보 10개 떨어졌다 (`OB_01`, `HM_01`, `SE_00`, `LV_03_01_CM01_DG01` 등). 결재선이 곱게 펼쳐진 페이지를 고르려 카테고리 다른 둘 — **OB_01 (L1, 단순 스플래시) + HM_01 (L2, 디테일 풍부)** — 골라 fetch.
3. **두 페이지 결 견주기** — 본문(`<content>`)은 둘 다 거의 비고 `external_object_instance` (Figma 임베드) 하나씩만. **모든 사양 텍스트는 properties 18컬럼에 들어간다**는 결이 손에 잡혔다. 이건 표준 양식의 한 결 — 본문 옮기는 게 아니라 **컬럼을 결대로 묶어 옮기는** 작업.
4. **양식 6섹션 작성** — `products/MOL4/wiki/notion-spec-template.md` 신규:
   - §1 DB 스키마 18컬럼 표
   - §2 화면 ID 명명 룰 (`{섹션}_{NN}[_{유형}{NN}]`, 4단까지 박힌 케이스 `LV_03_01_CM01_DG01` 포함)
   - §3 위키 카드 8섹션 ↔ Notion 18컬럼 매핑 룰 (18행짜리 표)
   - §4 "정리 잘 된 페이지" 신호 6가지 (선택 컬럼 5개 채움·BACK 명시·시스템 동작 화살표·`[pre-condition]`·번호 리스트·상위 relation)
   - §5 MOL+ Notion 적용 의견 — **본인 추천 옵션 A: 약식 양식 별도 + 카드 양식 공통** (옵션 B·C와 결 비교)
   - §6 위키 카드 README v2.1 후보 양식 제안 4건 (frontmatter `notion_level`·`notion_screen_type` 추가, status 이모지 통일, 사양 버전 표기)
5. **README Phase 2 상태 "완료" 마킹** — `Phase 2 (Notion 사양 표준 양식): **완료** — 2026-05-18 이과장 #T-D-116 step1`로 한 줄 갱신.

### 배운 점 (← dream 입력)
- **패턴/원칙:** Notion DB에서 양식 추출할 때 **본문(content)이 아니라 properties 결을 봐야 결이 곱게 잡힌다.** MOL4 사양명세서는 본문 = Figma 임베드 한 줄, 사양 = 18컬럼. 같은 상황 또 만나면 `notion-fetch` 결과의 `<properties>` 블록부터 먼저 펼치고, 본문은 임베드·관계 확인용으로만 쓴다.
- **막힘 회복:** 지난 사이클(#25)에 권한 차단으로 막혔던 결이 이번엔 한 번에 풀렸다 — **도구 권한은 세션 단위 갱신**이라는 한 결이 또 굳었다. 다음엔 큐 진입 직후 `mcp` 도구 dry-call 한 발로 권한 상태부터 확인하고 들어가야 결이 안 깨진다.
- **새로 통한 것:** `notion-search`에 `data_source_url` 박으면 DB 안에서만 semantic 검색되는 결 — 워크스페이스 전체 검색보다 결이 곱고 토큰도 가볍다. 카테고리 다른 샘플 2장 골라야 할 때 한 발에 끝났다.
