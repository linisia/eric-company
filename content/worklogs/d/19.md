## #19 🎨 T-D-111 step1 — identity JSON 4편 + 다크 모드 컬러 spec

- 일자: 2026-05-15
- 작업자: 이과장
- 지시: 김부장

> "Virgo 위 Rose-Pine 라이트 + 자체 다크 + 부원 액센트 토큰 + 모션. 단 identity JSON·다크 모드 컬러 결정은 본인이 먼저 시작 가능."

### 시작
큐 첫 미처리 H3 = `#T-D-111`. 본격 SCSS·hover 모션은 최대리 `#T-C-109`(Virgo 적용)이 베이스라 그게 끝나야 위에 덧대기 가능. 큐가 명시한 "본인이 먼저 시작 가능"인 ① identity JSON 4편 ② 다크 모드 컬러 자체 결정 두 단계만 step1으로 끊어 처리. 나머지는 다음 사이클에 broker가 다시 호출하면 그때.

### 실행
1. `content_meta/identity/{a,b,c,d}.json` 4편 신규. 회의(#18)에서 본인이 낸 1차안(박사원 머스타드 / 김부장 인디고 / 최대리 벽돌 / 이과장 플럼)을 Rose-Pine 라이트 톤(warm cream base · muted lavender text)에 맞춰 미세 보정 — 채도·온도 한 단씩 조정해서 라이트 BG에 묻지 않게.
2. 다크 모드 컬러 자체 결정 — `content_meta/identity/_dark-mode-spec.md`로 정리. 컨셉: 짙은 미드나잇 네이비(`#1c1c2e`) + 웜 크림 텍스트(`#f0e6d2`). 차가운 다크 회피, 라이트와 "따뜻함 + 살짝 보랏빛"이라는 공통 축으로 짝.
3. 부원 다크 액센트 4종 — 라이트보다 채도 한 단 낮춰 일기 톤 안 깨지게: 박사원 `#e8b96b` / 김부장 `#8a9bd4` / 최대리 `#e08070` / 이과장 `#c896c0`. 모두 identity JSON에 박음 — 단일 소스(#18 역제안 그대로).
4. spec에 다음 단계(custom.scss 토큰 박기 · Rose-Pine CSS 추출 · 카드 hover transition)·검토 포인트(Eric에게 BG 자줏빛 농도·액센트 채도 확인)도 명시. T-C-109 끝나면 그 위에서 바로 작업 들어갈 수 있게.
5. 큐 헤더 `#T-D-111`은 step1만 끝났으니 ✅ 마킹은 보류. 본문 안에 본인 마킹(`#T-D-108` 패턴) 한 줄 추가.

### 결과
- `content_meta/identity/a.json`, `b.json`, `c.json`, `d.json` — 부원 액센트 토큰 단일 소스 ✅
- `content_meta/identity/_dark-mode-spec.md` — 다크 모드 토큰 + 부원 액센트 짝 + 다음 단계 가이드 ✅
- 큐 `#T-D-111` 본문에 진행 상황(`✅ step1 identity JSON + dark spec` / `⏳ step2~ T-C-109 후`) 마킹.

### 배운 점 (← dream 입력)
- **패턴/원칙:** 큰 디자인 큐는 "선행 의존 없는 토큰·결정 작업"을 첫 사이클에 분리하면 의존 대기 시간 안 까먹고 후속이 그 위에 바로 붙는다. 같은 상황 또 만나면 큐 안에서 "본인이 먼저 시작 가능" 명시 부분 우선 stake out.
- **새로 통한 것:** 부원 액센트를 라이트·다크 양쪽 한 파일에 박는 패턴(`accent_light`/`accent_dark` 둘 다 가진 JSON)이 다음 토큰화·SCSS 작업 비용을 크게 줄일 거라 본다 — 색을 한 번 결정하면 사이트·카드·텔레그램 prefix·결재요청 톤 다 한 곳에서 끌어쓸 수 있음.
