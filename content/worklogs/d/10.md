## #10 🛠️ T-D-105 Phase 7 dream-cron step1 — 트리거 인프라

- 일자: 2026-05-15
- 작업자: 이과장
- 지시: 김부장

> "step1에서는 트리거 인프라만. 4-phase 로직은 step2."

### 시작
10:00, 큐 훑어서 첫 미처리 헤더 #T-D-105 잡음. spec(`publish_pending/d-007-T-D-103-dream-cron-spec.md`)에 흐름 다 잡혀 있어 본 step은 골격만 깎으면 됨.

### 실행
1. spec / 기존 `scripts/stop.sh` / `~/Library/LaunchAgents/com.ericcompany.broker.plist` 톤·구조 참고.
2. `scripts/dream-cron.sh` — 인자 `a|b|c|d [--dry]`. mkdir-lock으로 동시 실행 차단, 4-phase 함수는 stub (Phase 3는 step2에서 `claude -p` 채움). 헬퍼 `log()` 한 줄로 stdout + `~/.eric-company/dream-cron.log` 동시 기록.
3. `scripts/dream-cron-all.sh` — a→b→c→d 순차 호출. 한 명 실패해도 다음 진행 (`set -e` 우회용 `if ! ... then warn`).
4. `~/Library/LaunchAgents/com.ericcompany.dream-cron.plist` — `StartCalendarInterval Hour=3 Minute=0` 매일 03:00 KST. `RunAtLoad=false`(인프라만이라 load 즉시 실행 위험 회피). PATH에 `~/.npm-global/bin` 명시 (#9 결재 사유 그대로 반영, hook PATH 버그 같은 종류 미연 방지).
5. dry-run — `dream-cron.sh a --dry` 호출. exit 0, 4-phase stub 로그 다 찍힘. `mkdir -p`로 로그 디렉토리도 자동 생성 확인.
6. `plutil -lint` plist OK.

### 결과
- `scripts/dream-cron.sh` ✅
- `scripts/dream-cron-all.sh` ✅
- `~/Library/LaunchAgents/com.ericcompany.dream-cron.plist` (lint OK, **launchctl load 보류** — 결재 후 실서비스화) ✅
- dry-run 로그 `~/.eric-company/dream-cron.log` ✅

### 배운 점 (← dream 입력)
- **패턴/원칙:** spec → 구현 분할이 정확히 들어맞을 땐 골격부터 깎고 phase 내부는 stub으로 비워둔다. step1에서 phase 로직까지 욕심내면 step2 회수 어려움. **인프라 step에서는 "지금은 채우지 않음"이라는 stub 로그 한 줄을 의도적으로 남겨, step2가 어디부터 시작인지 자기 추적되게.**
- **새로 통한 것:** `flock`은 macOS 기본 미포함이라 `mkdir`-lock으로 대체. trap으로 정리하면 동등 신뢰성. broker plist는 `KeepAlive=true` 데몬형이지만 dream-cron은 daily 1회라 `RunAtLoad=false + StartCalendarInterval`이 정답.
- **막힘 회복:** 첫 dry-run에서 lock 충돌 안 났는지 의심해 두 번 호출 — 두 번째도 정상이라 trap+rmdir이 동작 확인. 다음에는 lock 확인하려면 한 번은 백그라운드로 띄워서 동시성 체크하는 게 더 정확.
- **역제안 누적:** 큐 지시는 `com.ericcompany.dream-cron.plist`였고 spec은 `com.aloys.eric.dream-cron.plist`였는데, 기존 broker가 `com.ericcompany.broker`라 일관성 위해 큐 지시(`com.ericcompany.*`) 채택. 다음엔 spec 작성 단계에서 prefix 정합성 먼저 잡고 시작.
