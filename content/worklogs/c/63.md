## #63 🔬 GA4 (not set) 구조 완전 규명 + 개발팀 설명 문서 (자동/수동 screen_view 중복)

- 일자: 2026-06-02
- 작업자: 최대리
- 지시: Eric (#62 이어서 — 심층 질문 핑퐁)

> "화면이름은 잡히는데 screen_id/category가 (not set)인 게 뭔지? event_name이 (not set)인데 화면이름은 잡히는 건? user_engagement가 어떤 화면엔 왜 없지? 이걸 분석해서 개발팀에 '이래서 not set이다 + 없애려면 이래야 한다' 설명해줘."

### 시작
#62 마무리 후 Eric이 "Screen ID 접속현황(`DtVwIR`) 표에 화면이름은 있는데 id/category가 다른 내용"이라며 심층 질문. Eric이 직접 측정기준에 `이벤트 이름`을 드래그로 추가(내가 못 잡는 부분 → Eric 수동 협업).

### 실행
1. 측정기준 4교차(`Category × ID × 화면이름 × 이벤트이름`) 115행 빈셀 포함 정밀 추출 + 측정값(사용자수·체류) 집계.
2. 결정적 패턴 발견: **screen_id 붙은 행은 100% `screen_view`**. 같은 화면에 자동 screen_view(id없음)+수동(id있음) **두 줄**.
3. Eric 배경정보로 확정: `logScreenView(firebase_id, screen_id, category)`를 개발자가 screen_view에 수동으로 심음 → 그래서 screen_view 전용 + 한 쌍.
4. 현상 6종 분류(A 정상~F 라벨오타) → 개발팀 설명 문서 작성.
5. **Eric이 권고 순서 교정**: 내가 `FirebaseAutomaticScreenReportingEnabled=NO`를 1순위로 뒀는데, Eric이 "자동 끄면 미계측 화면(TvSeriesScreen 등)을 GA에서 못 찾는다 → 계측 어디 빠졌는지 모르게 된다"고 지적. → 자동끄기를 최후 단계로 내리고 필터를 1단계로 재배치.

### 배운 점 (← dream 입력)
- **🚨 "지금 단계에 필요한 신호를 죽이는 조치"는 후순위로.** 자동 screen_view 중복이 짜증나도, 그게 지금은 **미계측 화면 탐지 레이더**다. 정리 권고 짤 때 "이걸 끄면 지금 내가 보려는 게 안 보이나?"를 먼저 자문. Eric이 이걸 잡아줌 — 나는 깔끔함(중복 제거)에 꽂혀 순서를 거꾸로 짰다. **또 만나면: 최적화/정리 조치는 "현 단계 관측 목적"과 충돌하는지부터 체크 후 순서 결정.**
- **계측 메커니즘은 이벤트 차원 교차가 결정타.** 화면×id만 볼 땐 "왜 not set"이 안 풀렸는데, `이벤트 이름` 한 축 추가하니 "screen_view 전용 + 자동/수동 중복"이 즉시 드러남. **막히면 차원 하나 더.**
- **firebase_screen(자동) vs screen_id(수동 logScreenView)** 는 출처가 달라 안 맞물리는 게 정상. (not set) = ①다른이벤트(정상) ②네이티브 미계측 ③자동 중복 ④event_name notset 노이즈.
