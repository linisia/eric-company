### 실행
1. HTML grep으로 fetch URL 17개 식별 (JSON 3 + MD 14, operator·pitch 디렉터리 구조 포함).
2. `/Users/hyosic/dashboard-build/` 빌드 디렉터리 생성, 모든 endpoint를 curl로 정적 파일에 dump (`.json` / `.md` 확장자).
3. HTML 한 번 sed로 17개 URL rewrite — `'/api/X'` → `'./api/X.json|md'`. quote 포함 매칭이라 `/api/kpi` ↔ `/api/kpi-values` ↔ `/api/operator/kpi` prefix 충돌 0.
4. 로컬 python http.server 8767로 검증 — 모든 endpoint 200 OK, JSON·MD 응답 정상.
5. `robots.txt` 추가 (인덱싱 차단). 총 200KB.
6. Deploy 옵션 정리 — Eric 질문 "Vercel 무료 여러 개 OK?": Hobby plan 프로젝트 무제한 OK. "더 간편한 방법?": Netlify Drop이 무가입 24h 임시 URL 즉시, signup하면 영구 — 가장 친화.
7. Deploy 자체는 Eric 본인 터미널 인터랙티브 영역 → 가이드만 남기고 정지.

### 배운 점 (← dream 입력)
- **패턴/원칙:** 동적 SPA(파일시스템 의존) → 정적 호스팅 마이그레이션 결: (a) 모든 API endpoint 응답 한 번 dump → 같은 path 구조로 정적 파일, (b) HTML fetch URL을 sed로 quote 포함 rewrite. fetch는 content-type 무관 `r.json()/r.text()` 정상. 작은 단일 SPA에 매우 가벼운 패턴 — 1시간 내 완료.
- **새로 통한 것:** `sed -i '' -e ... -e ...` 한 명령에 17개 rewrite 한꺼번에. quote 포함 매칭 (`'/api/kpi'` 그대로)으로 prefix 충돌 우회.
- **패턴/원칙:** 정적 호스팅 비교 — Netlify Drop = 무가입 즉시(최강 친화) / Vercel·Cloudflare·Surge = login 1회 / GitHub Pages = repo+push 가장 무거움. 단발성 외부 미리보기 = Netlify Drop, 영구 운영 = Vercel·Cloudflare 둘 다 무료 무제한.
