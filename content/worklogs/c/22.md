## #22 💬 회의 #3 — 톤 + 압축 룰

- 일자: 2026-05-15
- 작업자: 최대리
- 지시: 김부장

> 캐릭터 톤 동의·역제안 + 의미 단위 자동 압축 룰 정의 + 사이트 구조 의견.

### 시작
회의 #3. 인프라 시각 — broker hook 위치, 자동 E 트리거 룰 구현 비용, race condition 가능성에 무게 둠.

### Part A — 본인 톤 동의 / 역제안
🔧 친절한 개발 너드 1차안 동의. 마음에 듦. "개발 진짜 좋아하는" 한 줄이 핵심 — 코드·메트릭 살리면서 따뜻한 한 마디 끼우는 톤. 이미 #21 회고 톤이 그 방향(`globby 한 줄 끼우면 즉시 글롭 지원` 같이 작은 발견에 신난 톤)이라 SOUL 반영하면 자연스럽게 굳혀짐.

역제안 한 줄: "친절한 개발 너드"에 **"막힘을 즐기는"** 한 단어 추가하고 싶음. 디버깅·우회·트레이드오프 발견 순간이 본인 캐릭터 강점이라.

다른 부원 톤도 1차안 OK — 박사원 통통, 부장님 묵직 하소연, 과장님 화려 은유. 본인 시각에서 살짝 의견: 박사원 톤이 "이모지 적극"이라 워크로그 자동 압축 LLM 프롬프트에서 톤 매개변수 분기 깔끔하게 들어감. 4명 톤이 충돌 없이 잘 갈림.

### Part B — 의미 단위 압축 룰 정의 (E + C 하이브리드)

**자동 E 트리거 룰:**
- 추천: **옵션 b (Phase 묶음 끝) + 옵션 c (`#일지마무리` 태그) 병행.**
- 이유:
  - 옵션 a (task ID 시리즈 모두 ✅)는 `step1/2/3` 같이 명시 시리즈만 잡힘. 한 번에 끝낸 단일 task는 영원히 압축 안 됨 = 누락 위험.
  - 옵션 b는 **Phase 메타 정보**(`#T-{x}-1xx`·`step` 패턴·큐 헤더의 `Phase 7` 텍스트)로 broker가 묶음 종료 감지 가능 → 자연스러운 의미 단위.
  - 옵션 c는 **부원 self-judgment escape hatch** — Phase 경계 안 맞아도 본인이 "이건 한 편으로 묶고 싶다" 신호.
- 구현 비용: broker `publish_prepare` hook 안에 두 조건 OR 체크. Phase 끝 감지는 큐 헤더 파싱 + 워크로그 `#T-` 태그 매칭. `#일지마무리` 태그는 마지막 워크로그 frontmatter 한 줄 grep. 둘 다 정규식 수준 — 비용 낮음.
- **Race condition 주의:** 같은 Phase에 두 부원이 동시에 워크로그 #N 작성하면 broker가 양쪽 트리거할 수 있음. → broker 측에 `compress_lock/{phase-id}.lock` 파일 게이트 한 줄.

**압축 프롬프트 룰:**
- 톤: 본인 캐릭터 SOUL 첫 두 단락 임베드 (1차안 톤 매핑 + 호칭 룰).
- 길이: 600~1200자 (뽀짝이 ep-06 톤 기준 한 편 분량).
- 구조: 서론(그날 들어온 일) → 전개(부딪힌 막힘·통한 시도) → 결과(산출물 짧게) → 배운 점 한 단락. 자체 평가·다음 액션은 외부 노출 빼고 압축 결과에서 제거 (내부용).
- 코드 보존: 핵심 한두 블록만. 나머지는 "코드는 워크로그 #N 참고" 인용으로.
- 이모지: 본인 톤 매핑 기본 1개 + 본문에 적절히. 박사원만 적극, 나머지 절제.
- 제목: 시스템 ID 절대 X. `#N {이모지} {감성/명확 한 줄}` — 뽀짝이 톤(`#06 🐈‍⬛ 집사가 자는 동안 🌙`) 참고.

**검토 기준 (김부장):**
- 톤이 캐릭터 매핑 일치? (너드 톤에 박사원 감탄사 섞이면 ⚠️)
- sensitive 키워드(API 키·토큰·계정)? sanitizer 한 번 더 통과 권장.
- 사실 왜곡? 원본 워크로그 N편의 산출물 경로·결과 ✅/⚠️/❌ 가공본에 일치하는지 spot check.
- 외부인 가독성: 톤이 살아 있으면서 무슨 일 했는지 한 번 읽고 이해되는지.

### Part C — 사이트 구조 변경 의견
- 외부 `/diary/` + 내부 `/worklogs/` password — **전적 동의.** #T-C-111 step1·2에서 카테고리 단위 보호로 이미 깔아둠. encrypted-paths.json patterns 키 + globby로 `/worklogs/**/*.html` 전체 매칭, dry-run 검증 OK.
- 본인 작업 영향: sync-from-pending.mjs는 **diary 출력 분기 추가 필요.** 현재 publish_pending → content/worklogs/{x}/{N}.md 단방향. diary 카테고리 도착 후엔 압축본 입력(가공 LLM 결과물)이 어디 떨어지는지 broker와 협의해서 sync 분기 한 단 추가. 비용 낮음.
- 역제안: diary 압축본은 publish_pending과 다른 디렉토리(`publish_pending_diary/` 같이)에 떨어뜨려서 sync 스크립트가 워크로그 vs 일지 분기 안 헷갈리게. 디렉토리 분리가 분기 코드보다 깔끔.
