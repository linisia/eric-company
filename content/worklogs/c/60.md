## #60 📊 MOL+ 스크린추적 진단 + GA4 한계 규명 + Looker Studio 시간대 차트 구축

- 일자: 2026-06-01
- 작업자: 최대리
- 지시: Eric (1:1 핑퐁, 긴 세션)

> "이전 세션 MOL+ GA4 설정 히스토리 확인" → screen_id/category 왜 안 보이나 추적 → GA4 시간대 차트 한계 → Looker Studio로 현지시간 차트 구축.

### 시작
Eric이 "지난주 screen_id/category 적용했는데 GA4 탐색 분석 어디에도 안 나온다"로 출발. 진단 → GA4 한계 규명 → Looker 전환의 긴 흐름.

### 실행 (핵심만)
1. **진단**: screen_id/screen_category는 **디버그 빌드에만** 들어갔고, 그것도 **맞춤 측정기준 등록(5/29)보다 먼저** 테스트 → GA4 비소급(non-retroactive)이라 DebugView엔 떴어도 보고서/Explore엔 영영 안 뜸. screen_view 매개변수(5/30~6/1) 12개 전부 자동, 커스텀 0개로 확정.
2. **Android Play Store 내려감**(저작권) 발견 → 업데이트 배포 불가 → **iOS 우선**으로 피벗 (iOS 56.9%로 더 큰 시장, App Store 살아있음).
3. **GA4 탐색 분석 정리**: 탭3(시간대 막대) 삭제, iOS/Android 세그먼트 생성·적용. 단 KST 왜곡·hour-of-day X축 불가 확인.
4. **Looker Studio 구축**: 보고서 생성 → GA4 연결 → 세로막대(X=시간) → **계산된 필드로 현지시간 변환** → 유럽 차트 완성(저녁 20~21시 피크). 북미는 핸드오프(`notes/ga4_explorer/2026-06-01_looker_studio_handoff.md`).

### 결과
- ✅ Looker 보고서 "(유럽) MOL+ 시간대별 이용 현황" 완성·저장
- ✅ 계산된 필드 2개(유럽·북미 현지시간) 생성
- ✅ 핸드오프 문서 = 북미 페이지 다음 세션 실행 단계 박음
- ⏳ screen_id/category = iOS 배포 후 데이터 (본 블로커)

### 배운 점 (← dream 입력)
- **GA4 vs Looker 경계**: GA4 탐색 분석은 ① hour-of-day를 X축에 못 놓음(막대 max10·값정렬 / 선=라인쪼갬 / 테이블=문자열정렬) ② 시간대 변환 불가. **둘 다 Looker 계산된 필드(`MOD(CAST(시간 AS NUMBER)+offset, 24)`)로 해결.** 시간대 분석 요청 = Looker로 직행.
- **GA4 맞춤 측정기준 비소급**: 등록 *이후* 이벤트만. DebugView(raw·즉시) ≠ Explore(등록·24~48h·볼륨). "디버그에서 봤다"≠"보고서에서 조회된다".
- **모바일 배포 = 앱 바이너리**: 서버 아님. 새 파라미터는 재빌드→스토어→사용자 업데이트(점진) 거쳐야 운영 데이터에 쌓임.
- **막힘 회복**: 같은 브라우저 Eric과 동시 클릭 → 내가 만든 세그먼트 사라짐(덮어쓰기/undo). **공유 브라우저는 단독 운전.** 새 작업은 별도 탭(Looker)에서 = 충돌 회피.
- **다음에 같은 상황**: "왜 커스텀 데이터 안 보이지" = ①등록일 vs 이벤트 순서 ②운영 빌드 포함 여부 ③DebugView raw 검증, 3종 먼저. 시각화 한계 부딪히면 GA4 고집 말고 Looker.

### 자체 평가
⭐⭐⭐⭐⭐ — 진단 정확(데이터로 못 박음), GA4 한계 솔직히 인정하고 Looker로 우회 성공, 유럽 차트 곡선이 프라임타임 피크로 의미까지 맞음. 세션이 매우 길었던 게 유일한 감점(브라우저 100+스텝). 다음엔 "GA4 시간대 차트 = Looker" 즉시 판단해 단축.
