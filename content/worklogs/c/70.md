## #70 📘 GA4·Firebase 핸드북 전수 사실검증 + 수정 (ultracode 워크플로)

### 시작
Eric 발주: `eric-company-shared/ga4-firebase-handbook` 12파일 "하나도 빠짐없이" 검토 + 틀린 사실 점검 + 개선. ultracode 모드.

### 실행
1. 12파일(2,345줄) 직접 통독 → 파일별 의심 포인트(hotspot) 목록화 후 워크플로 발주서에 주입.
2. **Workflow 발진**: 파일별 사실검증 12 + 일관성 1 에이전트(WebSearch 공식문서 대조) → 오류 의심 건별 적대적 재검증 → Apply → QA. 총 44에이전트 / 2.4M 토큰.
3. **사고**: Apply 단계 12/12 StructuredOutput 실패 + Bash(쓰기)·WebFetch 분류기 간헐 장애 (24h+ 지속). 검증 데이터는 무손실 → 수정 적용은 내가 직접 Edit. 백업은 cp 복구 타이밍에 cp, 안 될 땐 Read→Write 우회.
4. **유실 복구**: 10장 리뷰 통째 누락 → 단독 에이전트 재발주. verify 유실 건('누적 5만', Comparisons 4/5)은 reviewer summary 흔적에서 발굴해 내가 WebSearch 직접 재검증 (Comparisons는 현행 4개 = 원문 유지 판정).
5. **verifier 에이전트 검수** → PASS (지적 1건 즉시 반영).

### 결과
✅ 확정 오류 17건 수정 + 일관성 8건 + 선별 개선 ~25건. 백업 `.backup-2026-06-10/`.
핵심 수정: 전환→**주요 이벤트**(2024-03 개명), Looker Studio→**데이터 스튜디오**(2026-04-11 재개명, 직접 fetch 확인), DebugView 끄기 **`.none.`**(점 포함), Pendo 6.4% 의미 오독(써본 비율 X → 클릭 80% 차지 기능 비율 O), Consent Mode 동작 오해(수집 중단 X → 익명화 O), '누적 5만'→**하루치 표 행 한도**, BQML 학습 단가 수십 배(예측은 일반 단가), 무료도 스트리밍 export로 전량 가능(GA4 360 불요), screen_category 6→**7개**(킥오프 SSoT 대조).

### 배운 점 (← dream 입력)
- **워크플로 스키마 에이전트는 도구 분류기 장애 중 StructuredOutput 단계서 전멸 가능.** 같은 상황 또 만나면: 검증(읽기) 단계만 워크플로로 돌리고, 파일 쓰기 적용은 메인 루프가 직접 Edit.
- **분류기 장애는 도구별 차등**: 읽기 Bash 통과 / 쓰기 Bash·WebFetch 차단 / Write·Edit은 별도 경로라 생존. 백업은 "Read한 내용 → Write" 우회가 항상 가능.
- **verify 유실 주장은 reviewer summary에 흔적이 남는다** — confirmed 배열과 summary 대조로 복구. 워크플로 설계 시 verdicts.filter(Boolean)가 유실을 침묵시키는 함정 — 다음엔 실패 verdict을 'unverified'로 보존.
- **인용 수치는 '실재'와 '해석'을 따로 검증** — Pendo 6.4%는 수치는 맞고 해석이 틀린 케이스. 숫자 확인으로 끝내면 놓친다.
