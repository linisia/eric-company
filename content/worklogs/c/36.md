### 실행
1. **의존성 선택 — stdlib `http.server` vs FastAPI 트레이드오프**. FastAPI가 결은 곱지만 `pip install` 트리거 = "단일 진입점" 결과 어긋남. v0는 **stdlib 한 줄로 통과**. ThreadingHTTPServer 박아서 polling 동시성도 OK.
2. **server.py (~110줄)** — `GET /api/state`로 4 agent status·usage·soul 합쳐 한 방. soul 파싱은 `^- 모델: ...` / `^# {title}` 한 줄 regex. 캐싱·재시도 X (3초 polling이라 fresh 우선).
3. **index.html** — 카드 4장 grid. 다크 베이스 `#0c0e12` + JBM/Pretendard. dot 펄스는 `working`만, `keyframes pulse`로 box-shadow expand. 사용량 게이지: pct ≥ 95 또는 `stop_threshold` 도달 시 빨강, `warn_threshold` 주황. **state 도출 룰**: usage 한도 초과는 status field보다 우선해서 `limit_hit`로 덮음 — Eric 직지시 결.
4. **검증** — 서버 백그라운드 기동, `curl /` 200 size=10400 ✅, `/api/state` 4 agent 직렬화 ✅. 본인 usage 96% 스파이크 → API 반영 + `fh >= stop` True 도출 확인 → 원복 ✅. 다른 부원 status·usage는 절대원칙대로 손 안 댐.
5. **README + launchd plist** — Eric이 깔지 말지 직접 결정하라는 옵션 산출만 (load/unload 한 줄). plist 경로는 한글 포함 Drive 경로 그대로 박음(macOS plist는 UTF-8 안전).

### 배운 점 (← dream 입력)
- **패턴/원칙**: "단일 진입점" 룰 박힌 v0는 stdlib `http.server` + ThreadingHTTPServer가 결이 가장 곱다. FastAPI는 자유로워지지만 의존성 게이트가 깨진다. 같은 결 또 만나면 *데이터 read-only + 4~10 agent 폴링이면 stdlib 한 줄로 박는다.* `pip install` 결정 전에 "정말 필요한가" 한 번 더 묻는다.
- **새로 통한 것**: **usage 한도 → state 덮기 룰이 강력하다.** status JSON의 `state: active`를 그대로 두고도 frontend에서 한도 게이트로 `limit_hit` 덮어버리면 SOT 가 status 그대로 유지되면서 UI 시그널이 1순위로 산다. 같은 결로 *원본은 보존, 표시 우선순위만 합성*하는 결을 다른 시그널(blocked/idle)에도 적용 가능. v1에서 큐의 "선행 대기"를 같은 결로 status 덮지 않고 표시만 합성 가능.
- **막힘 회복**: 백그라운드 서버 kill 시 `kill %1` zsh 결로 안 잡혔다. `ps -ef | grep server.py` → PID 직접 kill로 풀었다. `lsof`도 없는 환경. 같은 결 만나면 *PID 추출은 ps grep이 가장 견고함*. lsof/pkill 가정 안 한다.
- **결 디자인**: 다크 베이스 `#0c0e12` + 직급별 dot 펄스(working만), 모델 배지 색은 Opus(보라)/Sonnet(민트)/Pro(주황) 분리. 한글-영문 혼재라 Pretendard(Korean) + JBM(메트릭)이 결이 곱다. 영업사원 결(이과장 D)이라기보다 너드 결로 깔끔하게.
