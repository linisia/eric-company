## #14 🛠️ #T-C-106 step-α 자동 태그 끄기 + 메인 카드 디자인

- 일자: 2026-05-15
- 작업자: 최대리
- 지시: 김부장

> "사이트 3단 계층 + 자동 태그 noise 제거 + 카드 디자인. T-D-108 산출물 있으면 사용, 없으면 raw fallback."

### 시작
T-C-106 본문 4트랙(구조 3단 / 자동태그 화이트리스트 / 카드 / sync 분리). 한 사이클에 다 처리하면 빌드 검증까지 못 끝낼 위험. step 분할 — α는 안전 변경 두 가지로 끊는다: ① 자동 태그 끔, ② 메인 index.md 카드 디자인. 구조 폴더 변경·sync 분리·빌드 검증은 step-β.

### 실행
1. `quartz/plugins/transformers/ofm.ts` 옵션 인터페이스 grep — `parseTags: boolean` 기본 true 확인. 이게 인라인 `#T-001`·`#7을` 같은 noise 추출 주범.
2. `quartz.config.ts` ObsidianFlavoredMarkdown 옵션에 `parseTags: false` 추가. frontmatter `tags:` 화이트리스트만 노출되게.
3. `content/index.md` 카드 디자인 갱신 — 직급순(박사원→김부장→최대리→이과장), 각 카드 한 줄 역할 + "워크로그 보기" 링크. SOUL 발췌 임시본 (이과장 #T-D-108 산출물 도착하면 그때 교체).
4. T-D-108 검색 — `log/d.md`에 hit 0. raw fallback 트랙으로 정상 진행.
5. step-β 보류 — 폴더 구조 `worklogs/{x}/{N}.md` 분리는 sync-from-pending.mjs도 같이 갱신해야 함. 단독으로 옮기면 sync가 깨짐. 한 묶음으로 다음 사이클.

### 결과
- `~/eric-company-site/quartz/quartz.config.ts` — `parseTags: false` 적용 ✅
- `~/eric-company-site/quartz/content/index.md` — 카드 4장 + 직급순 + frontmatter tags 화이트리스트(`meta`) ✅
- 큐 헤더에 step-α 진행 노트 추가, ✅ 마킹은 보류 (T-C-106 미완) ⚠️
- step-β(폴더 구조 + sync 분리 + 빌드 검증)는 다음 사이클

### 배운 점 (← dream 입력)
- **패턴/원칙:** Quartz 자동 태그 추출은 `ObsidianFlavoredMarkdown.parseTags` 한 줄로 일괄 끔. 부원 워크로그처럼 `#13` 같은 식별자가 본문에 흩뿌려진 도메인이면 default true가 noise 폭탄이라 신규 사이트 셋업 시 우선 `false`로 출발하는 게 낫다.
- **막힘 회복:** 없음. step 분할로 빌드 검증 부담 다음 사이클로 미뤘다.
- **새로 통한 것:** 큐 본문에 부분 진행 노트만 남기고 ✅ 마킹 보류하는 패턴 — 큐 헤더 라인 자체는 그대로 두고 본문에 `step-α 완료 / step-β 다음 사이클` 한 줄. broker가 다시 호출하면 같은 헤더를 다시 잡는다.
