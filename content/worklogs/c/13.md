## #13 🛠️ #T-C-105 publish auto-commit + PUBLISH.md

- 일자: 2026-05-15
- 작업자: 최대리
- 지시: 김부장

> "sync:pending 호출 후 content/ 자동 commit (push X) + 한 페이지 운영 매뉴얼. dry/real/commit 3단 분리."

### 시작
큐 첫 미처리 H3 = `#T-C-105`. #12 회신에서 김부장이 approved 마킹·트리거 둘 다 (A) 수동 결재한 직후. 본인 영역: auto-commit 옵션 + npm wrapper + PUBLISH.md.

### 실행
1. `scripts/sync-from-pending.mjs` 패치 — `--auto-commit` 플래그 + `autoCommit(syncedCount)` 함수. `git add content/` → `git diff --cached --quiet`로 staged diff 확인 → 있으면 `git commit -m "publish: sync N drafts (auto)"`. **push는 손도 안 댐** (사이트 노출 책임은 사람).
2. 안전망 4겹: (a) `--dry-run` 동시 지정 시 commit 미실행 한 줄 로그, (b) `syncedCount<=0` 이면 "0건이라 commit skip", (c) staged diff 0이면 "staged diff 없음 — commit skip", (d) commit 실패 시 stderr 그대로 노출.
3. `package.json` — `sync:pending:commit` script 추가. 기존 `sync:pending` / `sync:pending:dry` 유지 → 3단 분리 완성.
4. `PUBLISH.md` 작성 — 글자 다이어그램 1단 + 명령 3종 + approved 룰 + 트러블슈팅 3건(sanitizer flagged / sync errors / commit conflict). Eric/김부장이 한 페이지로 사이클 돈다.
5. 검증 — `npm run sync:pending:commit` 호출 → `scanned=38 approved=0 synced=0` + `[auto-commit] 0건이라 commit skip` ✅. approved 0건 환경에서 commit 게이트 정상.

### 배운 점 (← dream 입력)
- **패턴/원칙:** publish 자동화 설계 룰 — **(1) push 분리 절대원칙** (자동 push 금지, 사람 손이 마지막 게이트), **(2) dry/real/commit 3단 분리** (실수 비용 최소), **(3) "0건 skip" 류 무해 로그** (idempotent 호출이 안전해야 cron/hook 후속 부착이 쉬움). 다음에 다른 자동화 라인 깔 때도 이 3룰 그대로 가져간다.
- **새로 통한 것:** `git diff --cached --quiet` 의 exit code (0=no diff / 1=diff) 활용 — `git add` 후 실제 stage된 변경이 있는지 한 줄로 판별. content/ 외 변경이 같이 staged 됐는지까지는 안 보지만, 0건 commit·empty commit은 깔끔히 막힘.

### 자체 평가
⭐⭐⭐⭐☆ — 3단 분리·안전망 4겹은 깔끔. 실제 sync+commit end-to-end는 여전히 approved 0건이라 미검증 — Eric 첫 결재 1건이 떨어지면 그때 실증. 4점.
