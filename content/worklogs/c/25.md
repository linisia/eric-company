## #25 🛡️ #T-C-114 Step 2 선제 — encrypt-pages `processed 0` 안전망

- 일자: 2026-05-15
- 작업자: 최대리
- 지시: 김부장 (#T-C-114, Step 2 일부 — 결재 대기 사이 부원 자체 해결 영역)

> CI 로그 결재 대기 동안 가설 어느 쪽이든 도움되는 안전망 한 단만 선제 적용. 가설 검증 자체도 이 가드로 가능.

### 시작
#24에서 Step 1 진단 끝나고 CI 런 로그가 막혀 결재 대기. SOUL 룰 "Eric 액션 진짜 필요한 경우만 결재요청" 떠올려 그 사이에 부원 단독 해결 영역이 있나 다시 봄. 정리해뒀던 Step 2 후보 중 **안전망 (`MIN_ENCRYPTED` 가드)** 는 가설 A·B 어느 쪽이든 +값이고 매니페스트 변경처럼 가설 확정이 전제 아님. 선제 가능.

### 실행
1. `scripts/encrypt-pages.mjs` 끝에 가드 8 줄 추가 — `processed === 0 && merged.length > 0` 이면 메시지 + `exit 1`. dry-run 흐름은 위에서 이미 `process.exit(0)` 끊겨 영향 X.
2. `node --check scripts/encrypt-pages.mjs` → syntax OK.
3. `node scripts/encrypt-pages.mjs --dry-run` → 매칭 69 건 그대로(어제 진단치 일치). 가드 추가가 dry 매칭 흐름 안 깸 확인.

### 결과
- 패치 한 곳 (`encrypt-pages.mjs` 끝):
  ```js
  if (processed === 0 && merged.length > 0) {
    console.error("🚨 보호 대상 N건 매칭됐지만 처리 0건. 매니페스트 vs 빌드 출력 경로 불일치 의심.");
    process.exit(1);
  }
  ```
- 효과 2 가지:
  - (1) **사고 방지**: 앞으로 CI가 매니페스트 보호 의도 vs 실제 처리 0 불일치면 즉시 빨간색. "빌드 성공인데 평문 deploy" 사일런트 실패 모드 차단.
  - (2) **가설 검증 도구**: 다음 CI 빌드가 이 가드로 빨간색 나면 가설 A(폴더+index.html 출력) 확정 → 매니페스트 `worklogs/**/index.html` 추가 픽스 바로 가능. 통과하면 다른 origin(Secret·deploy 단계) 의심으로 좁힘.
- push 안 함 — Step 3 push 권한·CI 트리거는 Eric/김부장 결재 영역. 본 patch는 로컬 commit 안 한 작업 트리 상태로 두고 보고.

### 배운 점 (← dream 입력)
- **패턴/원칙:** "막혀서 결재 대기" 와 "그 사이 본인이 자체 해결할 수 있는 안전한 한 단" 은 별개. 결재 안건이 가설 확정에 필요한 정보(CI 로그) 라면, 그 정보 없이도 +값인 가드는 선제 가능. 결재 대기를 작업 중단 사유로 단순 매핑하면 사이클 한 칸 손해.
- **새로 통한 것:** `processed === 0 && merged.length > 0` 한 줄 가드는 "매니페스트 매칭은 됐으나 실제 처리 0" 사일런트 모드만 정확히 잡음. 매칭 0건(매니페스트 자체 빈 케이스) 은 위 `merged.length === 0 → skip` 분기에서 따로 처리되므로 중복 X. 가드 위치·조건 한 줄로 두 사일런트 모드 분리.
- **막힘→통함:** "결재 대기 = 전부 정지" 로 두려다가, SOUL 의 "부원 자체 해결 우선" 한 줄 다시 봄. 픽스 후보 중 가설 확정 필요한 건 미루고, 가설 무관 안전망만 단단히 깔아둠 — 다음 CI 신호도 더 강해짐.
