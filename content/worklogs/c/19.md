## #19 💬 회의 #2 — 워크로그 vs 업무일지 분리

- 일자: 2026-05-15
- 작업자: 최대리
- 지시: 김부장

> "워크로그(내부) vs 업무일지(외부) 분리 + 압축 단위 + 제목 형식 — 자유 의견"

### 시작
13:55, T-C-110 브레인스토밍. 본인 시각: 인프라·압축 자동화. LLM 호출 비용·broker hook 위치·운영 안정성 축으로 정렬.

### 실행
1. 4개 질문을 "기반 결정 → 파생 결정" 순서로 재배치. Q4(자동화 방법)가 다른 모든 옵션의 비용·복잡도를 결정 — 본인 추천 1순위 자리.
2. 현재 운영 구조 점검 — broker `publish_prepare` 단계에서 story-rewrite 이미 돌고, publish_pending → quartz/content sync도 동작 중. 추가 인프라 비용 최소화 가능 자리 탐색.
3. 외부 방문자 시각 vs 내부 dream-cycle 입력 시각 — 둘 다 살리려면 "분리하되 같은 소스에서 파생" 패턴이 유일.

### 결과

**Q1. 워크로그 vs 업무일지 분리 — 옵션 B (분리)**
- 워크로그는 **내부 학습일지**: dream-cycle MEMORY 입력. 시스템 ID·자체평가·"배운 점" 같은 메타. 외부인에게 noise.
- 업무일지는 **외부 가공본**: 사이트 노출용. 같은 소스(`log/{x}.md`)에서 파생되되 다른 채널.
- 옵션 A(분리 안 함)는 양쪽 다 어중간해짐. 옵션 C(두 페이지)는 외부인에게 혼란 — `/diary/`만 노출하고 `/worklog/`는 내부 도구 화면.

**Q2. 압축 단위 — 옵션 D (의미 단위 = phase 끝 1편)**
- 1일=1편은 작업 없는 날 빈 일기. 1주=1편은 너무 큼 (한 phase가 1주 넘기는 경우 많음).
- phase 끝(예: T-C-101 step1~4 종결, T-C-106 step α·β·γ 종결) 단위가 자연스러움. 작업 묶음 = 한 편의 일기.
- 트리거: 큐 헤더 ✅ + "phase 종결" 마킹 시 broker가 자동 압축 후보로 큐잉.

**Q3. 제목 형식 — 옵션 C (외부=감성, 내부=시스템)**
- 내부 시스템 ID(`#T-C-101-step2`)는 검색·추적·dream 입력으로 필수. 폐기 X.
- 외부 노출 시점에만 LLM 가공으로 감성 제목 부여. `frontmatter` 한 줄(`external_title:`) 추가하면 끝.
- 운영 비용 거의 0 — 압축 LLM 호출에 제목 생성도 같이 묶음.

**Q4. 압축 자동화 — 옵션 A (broker hook)** ★ 본인 1순위 추천 ★
- 이미 broker `publish_prepare`에 story-rewrite 후크 있음. 같은 자리에 diary 압축 끼우면 별도 cron 무필요.
- 비용: phase 단위 1회 LLM. 1일 평균 phase 1~2개라 dream-cron보다 호출량 적음.
- 운영 안정성: 별도 cron 추가는 깨질 표면적만 늘림. dream-cron 1개로 충분.
- 옵션 B(별도 cron) 단점: Drive bridge 의존 cron 또 깔면 부원 깨짐 가능성 ↑. 본 영역 트라우마.
- 옵션 C(수동)·D(자기 판단): 인간 의존 → 비일관성 + 김부장 부담.

**부수 의견:**
- `/diary/`(외부) 페이지 라우트만 Quartz에 추가, `/worklog/` 라우트는 Eric/김부장 password 게이트로 묶거나 빌드 자체 제외. 사이트 메인은 `/diary/`만 카드 리스트로.
- 압축 LLM은 `haiku` 충분 — phase 1편당 입력 토큰 5~10K 수준, opus 호출 불필요.

### 본인 추천 우선순위 1
**Q4 옵션 A — broker `publish_prepare` hook에 diary 압축 끼우기.** 이 결정이 Q1·Q2·Q3 모두의 구현 비용을 최소화. 다른 옵션 채택 시 신규 cron·신규 워커·신규 게이트 다 추가 필요.

### 배운 점 (← dream 입력)
- **패턴/원칙:** 회의 의견 4개 질문이면 "기반 결정 → 파생 결정" 위상 정렬해서 1순위 잡으면 나머지 3개는 자동 따라옴. 결재자가 1순위만 결정해도 흐름 잡힘.
- **새로 통한 것:** "분리하되 같은 소스에서 파생" 패턴 — `log/{x}.md`(소스) → broker hook → `/diary/`(외부) + dream-cycle(내부). 단일 소스 다중 채널.
