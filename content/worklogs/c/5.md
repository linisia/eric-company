## #5 🚧 #T-C-101-step3 phase A — deploy.yml + 결재요청

- 일자: 2026-05-14
- 작업자: 최대리
- 지시: 김부장

> "GitHub repo + Actions 자동 배포. 1번이 결재요청이라 phase 분할."

### 시작
큐 첫 미처리 H3 = `#T-C-101-step3`. step2 완료 확인(#4). 1번 = Eric repo 생성 결재요청 → 차단 요소. push 전 가능한 준비만 phase A로 처리, repo URL 받으면 phase B (init/remote/push).

### 실행
1. `which gh` — gh CLI 미설치 확인. 지시문대로 Eric web 생성 루트 채택.
2. `~/eric-company-site/quartz/` 현황 점검 — `.git` 이미 존재(Quartz clone), `origin`=`jackyzha0/quartz.git`. phase B에서 origin 교체 필요.
3. `.gitignore` self-ignore 문제 해결 (#3 다음 액션) — 첫 줄 `.gitignore` 제거. 이제 repo에 트래킹 가능.
4. Quartz `docs/hosting.md` GitHub Pages 섹션의 표준 deploy.yml 패턴 참고 → 우리 분기 `main`으로 수정해 `.github/workflows/deploy.yml` 작성. Pages artifact 업로드 + deploy-pages@v4.
5. **🔔 결재요청 Eric**: GitHub repo `eric-company` (public) 생성 + URL 회신 요청 — phase B 즉시 착수 가능.
6. 큐 헤더 ✅ **마킹 안 함** — repo URL 받아야 종결.

### 결과
- `.gitignore`: self-ignore 제거 ✅
- `.github/workflows/deploy.yml` 신규 — main push 시 npm ci + quartz build + Pages 배포 ✅
- 결재요청 신호: 본 워크로그 + 큐 헤더 그대로(미처리 표식)
- phase B 대기 항목: `git remote set-url origin <Eric URL>` → 첫 push → Settings > Pages 소스 = Actions 확인 → 가동 URL 캡처.

### 배운 점 (← dream 입력)
- **패턴/원칙:** 결재요청이 1번인 step은 **분할 처리**가 정답. 결재 대기 동안 yml·gitignore 같은 결정적 산출물은 미리 만들어두면, repo URL 떨어진 순간 push까지 1분 컷.
- **새로 통한 것:** Quartz 원본 `.gitignore`는 `.gitignore` 자체를 ignore — 사용자가 자기 ignore 설정을 덮어쓰는 워크플로 전제. repo로 발행할 거면 첫 줄 제거가 정석. (#3에서 메모해둔 게 phase A에서 즉시 해결로 이어짐.)
- **막힘 회복:** origin이 Quartz 원본에 박혀있음 발견 — phase B 첫 단계는 `git remote set-url`로 갈음, 새로 init할 필요 없음. clone 이력 보존이 commit hash 추적에 유리.
