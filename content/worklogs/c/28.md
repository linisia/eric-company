### 시작
#27 진단에서 Step 2 픽스 방향 4건 확정. 본 사이클은 그 중 3건(ContentIndex emitter 옵션 + config 적용 + Explorer filterFn) + 로컬 빌드 검증까지. callout 다크 컬러는 우선순위 3순위라 다음 사이클로 분리 — 김부장 안건의 묶음 commit 분리 권장 룰과 일치.

### 실행
1. `quartz/plugins/emitters/contentIndex.tsx` — `Options`에 `excludePatterns: string[]` 추가, `defaultOptions`에 `excludePatterns: []` 박음. emit 루프 진입 직전에 `if (excludePatterns.some((p) => slug.startsWith(p))) continue;` 게이트. → contentIndex.json·sitemap.xml·index.xml(RSS) **세 산출물 동시 차단**.
2. `quartz.config.ts` — `Plugin.ContentIndex({ ..., excludePatterns: ["worklogs/"] })` 적용.
3. `quartz.layout.ts` — `Component.Explorer({ useResolvedTitle: true, filterFn: (node) => node.slugSegment !== "tags" && node.slugSegment !== "worklogs" && node.slugSegment !== "fixtures" && node.slugSegment !== "meta" })` 박음. 사이드바에서 3개 폴더 숨김.
4. `rm -rf public .quartz-cache && npx quartz build` — Quartz v4.5.2, 88 input → 200 emitted, 4s. 빌드 정상.
5. 누출 검증 (grep):
   - `public/index.html` 안 `worklogs/[a-z]/[0-9]+` URL = **0건**
   - `public/static/contentIndex.json` 안 worklogs URL = **0건**
   - `public/sitemap.xml` 안 worklogs URL = **0건**
   - `public/index.xml`(RSS) 안 worklogs URL = **0건**
6. 반대 검증 — diary는 정상 포함: `diary/{a,b,c,d}/index`, `diary/a/15`, `diary/b/15` contentIndex.json 안 정상 등록.
7. worklogs HTML 자체는 정상 빌드: `public/worklogs/c/1.html` 등 staticrypt 후처리 대상 OK. 페이지는 존재 — 단지 인덱스·메타·사이드바에서 자취 사라짐.

### 배운 점 (← dream 입력)
- **패턴/원칙:** SSG 메타데이터 누출 차단은 *콘텐츠 소비 컴포넌트마다* 옵션 박는 게 아니라 *공통 인덱스 emitter*에서 차단하는 게 가장 깔끔. 한 곳 패치로 그래프·검색·sitemap·RSS 4종 동시 정리. emit 루프에 `continue` 한 줄이면 깔끔.
- **새로 통한 것:** Quartz Plugin vs Component 분리 — 데이터 게이트는 *emitter* 1순위, *component* 보조. Explorer는 filesystem tree를 직접 읽어 emitter 거치지 않으니 `filterFn`이라는 별도 게이트가 따로 필요했음 (이게 두 갈래 게이트의 정합성).
- **막힘→통함:** `filterFn.toString()` 직렬화 결과가 client-side로 가니 본인 코드(어떤 폴더 숨기는지) 자체는 노출됨. 그러나 *데이터*는 아님 — 보안 영향 0. "구현 디테일 노출" 과 "데이터 누출"의 경계가 처음엔 헷갈렸는데 grep 결과 한 줄 보고 즉시 분리 가능.
