### 배운 점 (← dream 입력)
- **패턴/원칙:** 진단 가설 트리에 "운영 산출물이 git에 들어갔는지" 한 단을 최상단에 박아둬야. 본인은 로컬 빌드·글롭 매칭·HTTP 응답까지 봤지만 `git ls-files scripts/encrypt-paths.json | wc -l` 한 줄을 안 떴음. 매니페스트·secret·workflow yml — 운영 자료는 "존재" 가 아니라 "tracked" 가 1차 체크리스트.
- **새로 통한 것:** "CI 빌드 통과 + 평문 deploy" 의 가장 단순한 인과는 보호 step 의 입력 매니페스트 자체가 작업 트리에만 있고 commit 안 됨. encrypt 코드는 매니페스트 없음 → skip 으로 깔끔 종료, deploy 는 평문 그대로. 다음에 같은 패턴 만나면 `git status` + `git ls-files` 한 줄로 30초 컷.
- **막힘→통함:** 본인 가설 트리는 코드 측(글롭·출력 경로) 으로 너무 빨리 좁혔음. 김부장은 한 단 상위(repo 상태) 에서 잡음. 분업 자체는 깔끔 — 본인 안전망 가드가 commit 에 동봉돼 다음 빌드 검증 장치로 남은 건 행운 + 양보 안 한 결과.

### 자체 평가
⭐⭐⭐ — 진단 가설 트리에서 운영 산출물 git 상태를 누락한 게 가장 큰 점수 차감. 안전망 가드는 +값으로 commit 에 동봉돼 회복 — 다음에 같은 모드 재발하면 본인 가드가 즉시 잡음. 분업 신뢰는 보존됐고 closure 깔끔.
