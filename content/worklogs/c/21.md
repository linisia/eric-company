## #21 🔧 #T-C-111 step2 — encrypted 매니페스트 글롭 + worklogs 보호

- 일자: 2026-05-15
- 작업자: 최대리
- 지시: 김부장

> step2: 매니페스트 글롭 패턴 + sync 디폴트 + 빌드 검증.

### 시작
step1에서 diary 자리 잡고 메인 메뉴 재편 끝. step2는 `/worklogs/**` 카테고리 단위 password 자동화. encrypt-pages.mjs가 명시 paths 리스트만 받던 구조라 글롭 지원으로 확장하는 게 본 작업의 핵심.

### 실행
1. `encrypted-paths.json` 스키마 확장 — `{paths, patterns}` 두 키. `patterns: ["worklogs/**/*.html"]` 추가. paths의 `fixtures/password.html` 도 유지.
2. `scripts/encrypt-pages.mjs` 글롭 지원 — `globby`(이미 dep)로 `public/` 기준 패턴 풀이. paths + patterns 머지 후 중복 제거·정렬. `--dry-run` 옵션 추가 — SITE_PASSWORD 없이 매칭 파일 리스트만 출력해 검증 가능.
3. 검증: `node scripts/encrypt-pages.mjs --dry-run` → 34건 매칭. worklogs/{a,b,c,d}/{N,index}.html + worklogs/index.html + fixtures/password.html. diary/* 는 매칭 X = public. 패턴 의도대로 동작.
4. `sync-from-pending.mjs` 디폴트 `공개:` 변경은 **불요** 판정 — 현 sync는 frontmatter `공개:` 필드 자체를 안 본다. 보호는 출력 카테고리(`/worklogs/`) 단위라 매니페스트 글롭으로 충분. 부원 워크로그 frontmatter 의미는 dream-cron 입력 라벨로만 남음.
5. deploy.yml은 이미 `quartz build → encrypt-pages` 호출 + SITE_PASSWORD secret 주입. 코드 변경만으로 다음 push에 자동 반영.
6. 큐 헤더에 step2 완료 메모 + ✅ 마킹.

### 결과
- `encrypted-paths.json` patterns 키 추가 (`/worklogs/**` 카테고리 단위 보호)
- `scripts/encrypt-pages.mjs` 글롭 + dry-run 지원
- dry-run scanned=34 (worklogs 33 + fixture 1), diary/* 매칭 X 확인
- sync-from-pending 디폴트 변경 불요 결론 — 카테고리 단위로 충분
- T-C-111 전체 완료 (step1 + step2)

### 배운 점 (← dream 입력)
- **패턴/원칙:** "frontmatter 필드별 보호" vs "카테고리 디렉토리 단위 보호" 두 축이 있을 때, 카테고리 축이 sync·encrypt 파이프라인 둘 다 단순화된다. 워크로그처럼 디렉토리 자체로 분리된 컨텐츠는 frontmatter 분기 필요 없음. 가장 거친 단위에서 보호 게이트 깔면 sync 스크립트는 게이트 무지(無知)해도 됨.
- **새로 통한 것:** 정적 paths 리스트만 받던 스크립트에 patterns 키 하나 추가하고 globby 한 줄 끼우면 즉시 글롭 지원. 매니페스트 구조 안 깨고 점진 확장. `--dry-run` 끼워두면 secret 없는 환경에서도 패턴 검증 가능 — CI·로컬·결재요청 검토 셋 다 같은 명령으로 확인.

### 자체 평가
