## #24 🔒 워크로그 비번 게이트 진단 — CI 빌드는 통과, encrypt step이 0건 의심

- 일자: 2026-05-15
- 작업자: 최대리
- 지시: 김부장 (#T-C-114, Step 1 진단)

> 라이브 사이트 워크로그 평문 노출 증상. 로컬 빌드·글롭 매칭 정상 → CI 측 origin 좁힘.

### 시작
김부장 지시 Step 1 — 로컬 빌드 + 글롭 매칭 + 라이브 상태 3축 진단. 핵심 가설: Quartz 출력 경로 불일치 / 빌드 실패 / Secret 미설정.

### 실행
1. `rm -rf public && npx quartz build` 로컬 풀빌드 — 81 input → 180 emit, 4s. 정상.
2. `find public/worklogs -type f -name "*.html"` — 68 건. 패턴: 평면 (`worklogs/b/1.html`, 폴더+index.html 아님). URL `/worklogs/b/1` 매핑 정상.
3. `node scripts/encrypt-pages.mjs --dry-run` — 매칭 69 건(fixtures 1 + worklogs 68). 글롭 `worklogs/**/*.html` 정확 매칭.
4. `curl -sI https://linisia.github.io/eric-company/worklogs/b/1` — HTTP/2 200, last-modified `Fri, 15 May 2026 06:24:01 GMT` (오늘 빌드). `grep -ic staticrypt` = 0.
5. `gh` CLI 미설치 — CI 런 로그 직접 못 봄.

### 결과
- 로컬 빌드·매칭은 깔끔. URL ↔ 파일 매핑 정상.
- 라이브 CI는 오늘 통과·deploy 완료. but staticrypt 마커 0 = encrypt step 자체가 `processed 0/N` 으로 끝났거나(매니페스트 missing skip) staticrypt 가 평문 덮어쓴 경우 가능.
- 후속 후보 1순위: **`Fetch Quartz Theme` 스텝(`action_v1.sh`)이 quartz 설정·layout 덮어써 CI 빌드 출력 경로가 로컬과 달라졌을 가능성**. 만약 CI에서 `worklogs/b/1/index.html` 식 폴더 구조로 뽑히면 글롭 `worklogs/**/*.html`은 매칭하지만 `target = public/worklogs/b/1.html` 은 없음 → `[encrypt-pages] missing → skip` → processed 0 → 평문 deploy. 빌드는 통과.

> 🔔 결재요청 김부장: gh CLI 미설치 — CI Actions 런 로그 직접 확인 못 함. Eric에 gh 설치 결재 or Eric이 web으로 최근 deploy run 로그(`Encrypt password-protected pages` step 출력 한 줄: `완료 — N/M 페이지 암호화` 또는 `보호 대상 0건 — skip`) 한 컷 떠 주면 다음 사이클에 Step 2 픽스 확정 가능. Step 2 후보 픽스 2 가지 미리 굳혀둠:
> - 가설 A 확정 시: 매니페스트 patterns 에 `worklogs/**/index.html` 추가 (양쪽 출력 구조 대응).
> - 어느 쪽이든 안전망: `encrypt-pages.mjs` 에 `MIN_ENCRYPTED` 가드 추가 — `processed === 0 && merged.length > 0` 이면 exit 1 (다음 빌드 빨간색으로 빨리 잡힘).

### 배운 점 (← dream 입력)
- **패턴/원칙:** 보호 가드는 "빌드 성공 ≠ 보호 OK"를 가정해야 함. encrypt step 이 `processed 0` 으로 조용히 끝나면 CI는 초록색·사이트는 평문이라 사고가 늦게 잡힘. 보호 수가 매니페스트보다 작으면 fail 하는 안전망이 핵심.
- **새로 통한 것:** Quartz 4 기본 출력은 평면(`x/1.html`)이지만 외부 테마(quartz-themes/action_v1.sh) 가 layout 덮어쓰면 폴더+index.html 로 뒤집힐 수 있음. 글롭 패턴은 양쪽 다 매칭하지만 in-place 암호화 코드는 `path.basename(target)` 한 단계라 폴더 구조 바뀌면 missing skip. 매니페스트 패턴·코드 둘 다 양쪽 구조 대응이 안전.
- **막힘→통함:** gh 없어서 CI 로그 직접 못 봄. 막힘. 대신 라이브 사이트 `curl -I` last-modified + `grep -ic staticrypt` 두 줄로 "빌드는 통과, encrypt 만 안 됨" 까지 좁힘. 다음 사이클에 결재 받고 픽스.
