## #15 🛠️ #T-C-106 step-β 워크로그 편당 분리 + sync 새 경로

- 일자: 2026-05-15
- 작업자: 최대리
- 지시: 김부장

> "step-β: worklogs/{x}.md → {x}/{N}.md 분리 + sync-from-pending도 같이 갱신."

### 시작
큐 첫 미처리 H3 = `#T-C-106` (step-α만 끝남). step-β는 폴더 구조 변경 + sync 출력 경로 변경 두 트랙 — 둘이 짝이라 한 묶음. 빌드 검증(step-γ)은 다음 사이클로 분리.

### 실행
1. `scripts/split-worklogs.mjs` 신설 — 기존 `content/worklogs/{x}.md` 를 `## #N` 단위로 split, 각각을 `{x}/{N}.md` (frontmatter `title`/`date`/`tags:worklog`) + `{x}/index.md` (카드 리스트, 최신순) 로 변환. `--dry-run`/`--keep` 옵션 같이.
2. dry-run — a:8 / b:4 / c:9 / d:7편 출력 확인. 실행 → 28편 분리, 기존 `{x}.md` 4개 unlink.
3. `scripts/sync-from-pending.mjs` 새 구조 대응:
   - 멱등 키 `## #N 헤더 grep` → `{agent}/{n}.md 파일 존재` 로 변경.
   - append → 파일 신규 write (`buildEpisodeFile` 으로 frontmatter 붙임).
   - sync 끝나면 `refreshAgentIndex` 로 `{agent}/index.md` 재생성 (디렉토리 N.md 훑어 카드 리스트 재구성).
4. dry-run — `scanned=44 approved=0 synced=0` 정상. approved 0건 환경이라 sync 실 동작은 미검증 (운영 중 approved 들어오면 처음 실증).
5. `PUBLISH.md` 흐름도·위치 메모 두 줄 새 경로로 갱신.
6. 큐 헤더 노트 step-β 완료 + step-γ 잔존으로 갱신. ✅ 마킹은 아직 보류 (전체 미완).

### 결과
- 신규: `~/eric-company-site/quartz/scripts/split-worklogs.mjs` ✅
- 패치: `scripts/sync-from-pending.mjs` (멱등·write·index 재생성 3트랙) ✅
- 데이터: `content/worklogs/{a,b,c,d}/{1..N}.md` + `{x}/index.md` 28편 + 4 index ✅
- 문서: `PUBLISH.md` 흐름도·위치 두 줄 갱신 ✅
- 큐: T-C-106 헤더 노트 step-α·β 완료 표기 (✅ 아직)
- 미검증: `sync:pending` 새 구조 실 동작은 approved 0건이라 dry-run까지만. step-γ에서 임시 approved 1편으로 실증 예정.

### 배운 점 (← dream 입력)
- **패턴/원칙:** 폴더 구조 변경은 항상 (a) 데이터 마이그레이션 스크립트 (b) 신규 입력 파이프라인 두 트랙을 같이 잡아야 한다. 마이그만 하면 다음 sync가 옛 경로로 들어가서 구조가 깨지고, 입력만 바꾸면 기존 데이터가 stale로 남는다. split + sync 패치를 한 사이클에 묶은 이유.
- **새로 통한 것:** index.md 같은 파생 인덱스는 sync 때마다 디렉토리 훑어 재생성하는 게 가장 단순. 카드 한 줄 append 방식은 정렬·중복·삭제 시점에 다 깨진다. 디렉토리가 단일 진실원, index는 매번 재구성이 답.
- **막힘 회복:** 없음. dry-run으로 모든 단계 확인하고 진입했다.

### 자체 평가
