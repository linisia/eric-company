## #7 🚧 #T-C-101-step3 phase B — origin 교체 + 첫 commit, push 차단

- 일자: 2026-05-14
- 작업자: 최대리
- 지시: 김부장 (broker 재호출, 큐 헤더에 Eric repo URL 박힘)

> "[phase B 진입 — Eric repo: https://github.com/linisia/eric-company]"

### 시작
큐 헤더에 Eric repo URL 회신 반영됨. phase A 산출물(deploy.yml + .gitignore self-ignore 해제) 그대로. phase B 착수.

### 실행
1. `git remote set-url origin https://github.com/linisia/eric-company.git` — Quartz 원본에서 Eric repo로 갈음.
2. `git checkout -b main` — deploy.yml 트리거 분기 = main. 기존 `v4` HEAD에서 분기.
3. `git config --local user.{name,email}` 신원 셋업 (linisia / noreply 형식). global 미터치.
4. `git add .gitignore .github/workflows/deploy.yml content/ scripts/` → `git commit` — 13 files, +1124/-1.
5. `GIT_TERMINAL_PROMPT=0 git push -u origin main` → ❌ **fatal: could not read Username** — osxkeychain에 GitHub 자격증명 캐시 없음, prompt 차단으로 fail-fast.

### 결과
- origin 교체 ✅ (linisia/eric-company)
- main 브랜치 + 첫 commit `e137f5e` ✅ (local only)
- push ❌ — credential 차단
- 가동 URL: 미확보 (push 차단)
- 큐 헤더 ✅ **마킹 안 함** — push 완료 시점까지 보존.

### 배운 점 (← dream 입력)
- **패턴/원칙:** 비대화 환경의 첫 push는 항상 credential 차단을 가정해야 한다. `GIT_TERMINAL_PROMPT=0`을 default로 두면 hang 없이 fail-fast — broker 흐름 보존.
- **새로 통한 것:** Quartz clone 위에 origin set-url + 새 분기로 main 만들기 = 새 init 없이 fork 효과. clone 히스토리 보존(권리 출처 추적 유리), 첫 push만 통과하면 Pages 표준 패턴.
- **막힘 회복:** push 차단점은 결재요청으로 즉시 패스. local commit은 이미 안전하게 잡혀있어 자격증명 들어오면 1회 push로 즉시 종결 가능.

### 자체 평가
⭐⭐⭐⭐ — 가능한 산출물(origin·main·commit)은 다 깔아둠. 차단 사유는 외부 권한, 본인 영역에서 풀 길 없음. step3 종결까지 1단계 남음.
